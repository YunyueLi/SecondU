# 独立桌面产品审查

审查日期：2026-09-29。范围：`docs/API.md`、`docs/PRODUCT.md`，以及 `server/`、`src/`、`desktop/`、共享契约和现有测试。只使用虚构临时数据、本机 HTTP 提供方和注入式运行时夹具；未读取用户密钥，未请求第三方模型，未打开浏览器，也未改生产代码。

结论：本次发现的三个后端阻断项已由实现者修复，新增 11 项独立回归全部通过；完整套件共 42 项，40 项通过、2 项真实运行时可选检查跳过、0 失败。浏览器／原生视觉与真实提供方能力不在这个通过结论内。桌面应用连接开发资料空间的问题仍列为建议 S2。

这是首个可运行桌面版本的产品与状态审查，不是完整安全审计。原生视觉、实际 Codex 沙箱行为、真实提供方能力由对应验收另行确认。以下保留原发现与修复验证，避免把曾经的问题或验证边界抹去。

## 已闭合的阻断发现

### R1：连接测试把非 Responses 结果报告成成功

- 位置：`server/index.mjs` 的 `POST /api/settings/provider/test`。
- 复现：本机模拟提供方返回 HTTP 200 和 `{}`，接口返回 `ok: true`，文案称“提供方已响应一次文本请求”。
- 影响：配置了错误端点、返回其他 JSON 的代理、未完成或空响应，都可能被误标成已连通。这不能作为 DeepSeek 或任意兼容模型已经运行的证据。
- 修复要求：核对 Responses 结果的结构、完成状态和实际非空文本输出；错误、未完成和非响应对象不能通过。
- 修复与复核：新增 `server/provider-test.mjs`，拒绝空对象、错误、未完成及无非空文本的响应。独立回归通过。

### R2：旧配置的测试完成后污染新配置的状态

- 位置：同上，异步网络请求结束后写 `lastTest` 的代码。
- 复现：开始测试 model-A；请求挂起期间保存 model-B；A 成功后，B 的设置出现通过记录。
- 影响：模型、地址或凭据换过以后，界面仍可能给当前配置错误的连通证明。
- 修复要求：把结果绑定启动测试时的配置及凭据版本；过时请求明确返回 409 或仅返回带旧配置身份的结果，不能写当前配置的 `lastTest`。同地址、同模型下轮换密钥也应失效。
- 修复与复核：配置代次与模型／地址／接口／思考深度／密钥身份快照共同判定归属；过时结果返回 409 `stale_provider_test`，不写入当前配置。模型变更和仅轮换密钥两项独立回归均通过。

### R3：任务只收到来源 ID，无法查看选中认知的证据

- 位置：`server/runner.mjs` 的 `contextFor`、`buildPrompt` 与 `execute`。
- 复现：来源明确写“只能周二，周三不行”，认知仅概括“偏好工作日”；选中这条认知并要求查证具体日期。发送给运行时的内容只有概括与 `sourceIds`，没有来源文字，运行时也没有受控证据读取入口。
- 影响：页面可查证不代表执行器能查证；目前无法闭合“来源证据 → 本人理解 → 判断与行动”的核心链路。模型若给出具体日期只能猜测或重新问用户。
- 修复要求：只对明确选中的认知提供关联来源的有限摘录，或提供受控只读证据文件／工具；保留来源身份、示例状态与截断说明，写入本轮快照。不能借此读入整个人物库或扩大私人资料发送范围。
- 修复与复核：新增 `evidenceFor`，仅提供所选事实关联的来源，单源最多 3000 字符、总共最多 12000 字符、最多 20 份；携带原文 SHA-256、demo、截断和省略标记，并记录独立 evidence 事件。来源以非指令材料加入本轮 prompt。选择隔离、具体证据可用性、预算及 demo 标记回归均通过。

## 已发现并交由产品实现者修复的界面问题

1. **成果草稿与后台新版本**：`ArtifactWorkspace.tsx` 原以 `draft !== artifact.content` 判断草稿，后台更新会把原本干净的旧内容误判为用户修改；哈希路由切页也不触发 `beforeunload`，原草稿会丢失。现代码已改为独立 `baseContent`，并在 sessionStorage 暂存草稿。需浏览器验证“未编辑时自动同步”和“编辑后跨页返回仍在”。
2. **历史任务认知被改写展示**：`AssistantWorkspace.tsx` 原直接显示最新 `data.facts`，纠正事实后，旧任务也显示新内容并称“参考了”。应展示实际执行快照，并与当前版本分别呈现。修复已交前端；本审查不把代码更新当作浏览器验收。
3. **从认知页面发起任务强制演示**：认识我、当前生活、Agents 的回调原未提供 mode，直接进入默认 demo，无法在该路径选择真实模型。应先进入预填的任务编辑器，让用户确认上下文与执行方式，再启动。
4. **人物关系及对话缺少用户入口**：关系页原只能看示例，缺少创建／纠正；对话空态引导“导入原文”，但资料导入只生成 sources，不会生成 conversations。主代理已补独立表单、来源关联和结构化对话导入；需实际操作验证，尤其导入校验失败时不留下假对话或部分关系。

## 已复核的保护及非阻断建议

- **成果并发写保护**：live 执行期间用户 PUT 成果已返回 409，要求先停止运行，避免执行器直接写磁盘而绕过数据库版本检查。独立回归第三项通过；这项保护应保留。demo 的版本冲突仍由现有后端测试覆盖。
- **审批与重启状态**：代码为每次操作创建独立审批；失效审批返回冲突，重启将旧 running／awaiting_approval 变为 interrupted，并拒绝旧 pending 审批。没有看到把上次批准直接转成后续全局许可的实现。
- **密钥与路径**：密钥从独立权限受限文件读取，导出不包含凭据字段；运行时使用单独 home、禁继承 shell 环境、独立任务目录和单次审批。上述是代码边界，不能替代实际安装版本的沙箱测试；本审查没有读真实凭据。
- **S1，已修复部分成果恢复**：原实现只在所有角色成功后登记成果，失败或取消前的文件无法通过成果入口查看。现已在运行时清理结束后收录允许的顶层文本文件，使用 `reviewStatus: pending` 与 `artifact_pending` 事件，任务继续保持 failed／cancelled；失败、取消两条回归通过。收录边界为单文件 1 MiB、总计 5 MiB、最多 50 份，拒绝符号链接及非 UTF-8，冲突保留用户版本。界面待验收标记仍须由前端验收确认。
- **S2，建议明确桌面连接的本地空间**：`desktop/main.cjs` 只按 health 中的应用名与版本复用 58645 端口，未核对目标 dataDir。开发服务与打包应用同时存在时，打包应用可能打开开发空间。宜绑定实例／数据空间身份，或明确告知正在连接哪个空间。
- **S3，已修复证据修订保留**：source PUT 现在返回 405，纠正通过新增来源；新建事实及后续修订保存 kind/sourceIds，旧历史缺失字段不猜填。来源不可覆盖、旧认知证据关联仍可追踪的回归通过。
- **S4，已修复重复自动化**：同一自动化有 active／queued／awaiting_approval／needs_input 等待处理任务时，手动重跑返回 409，定时触发跳过并推进下次时间，来源触发跳过且记录事件。等待审批和缺少模型配置两种状态的防重叠回归通过。
