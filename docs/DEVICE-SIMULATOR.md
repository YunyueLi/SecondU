# 跨端 Dev 交互模拟

2026-09-29，工作树实现。入口为 `#devices`，组件 `src/DeviceSimulator.tsx` 无外部 props；`src/deviceSimulation.ts` 是可独立测试的纯状态机。

这是一页可操作的产品流程演示，延续虚构产品工程师林遥在社区咖啡馆收到内测反馈的故事。所有状态只在页面内存中；没有相机、麦克风、音频播放、蓝牙、设备配对、真实网络队列、模型请求或文件写入。不读取真实任务与私人资料，退出或重置不会修改实际任务。

## 页面迭代与当前主流程

用户指出首版看起来像技术测试板，不易理解。首版大眼镜线图、任务编号与写入计数常驻布局被否定，不能将其截图当成视觉验收通过。

当前改为三个故事场景，一次突出一个设备：现场记一句话并澄清意图，桌面拿到可编辑清单，手机查看确认卡。首次只需“开始这段演示”，再按下一步接续。设备能力、噪音、主动观察、临时断网、过期确认、停止播报与取消仍可操作，放在“试试中断、断网与其他情况”中；任务编号和事件记录进一步收进详情。纸上花园图片是场景示意，不是采集到的现场图像。

该版已完成 JSX 语法检查，仍待实际 App 窗口验证三步流程、手机比例和桌面编辑，以及旧版本/断网边界。状态机测试结果保留，不能替代本轮视觉验收。

## 可以演示的链路

1. 眼镜通过文字模拟口述，或在开启相机能力后模拟主动观察。观察先提出候选，用户确认后才成为本轮任务来源。没有相机时不能读取图像；没有音频能力时不能使用口述或播报；关闭显示后现场便签不再呈现眼镜的短反馈。
2. 新输入必须澄清要完成的事情。可加入噪音，演示不确定输入先求证；可停止播报或打断补充，两者都不取消任务。
3. 桌面根据固定规则整理一份明确虚构的草稿。修改保存会产生新的任务修订；来源仍为候选，不自动写成长期事实。
4. 手机获取某一确切修订，内容、任务标识、修订与有效期一起冻结。手机确认仅模拟保存当前内容，不代表同意发送给第三方。旧修订与过期确认被拒绝，需重新获取与审阅。
5. 手机离线确认先等待；手机和桌面均恢复时再检查版本与期限。同一确认事件只记一次模拟写入。可重发同一确认，直接观察次数没有增加。桌面离线也不会提前写入。
6. 取消任务清除等待确认，旧确认不能恢复任务。已经完成的模拟动作不通过“取消”倒写撤销。重置会产生新的演示任务标识。

## 状态与约束

- 三种设备引用一个 `taskId` 与单调递增的 `revision`，没有复制三个任务冒充接续。
- 手机审阅是快照；桌面新修订不会静默更新手机已经看到的内容。
- 确认包使用唯一 `eventId`，绑定 `taskId`、`revision`、内容及有效期。处理结果保留在事件记录；重复、过期、取消后的确认均有明确反馈。
- 模拟时钟由“让确认超过有效期”显式推进，确认有效期为 5 个模拟分钟。它不是设备真实时钟同步或可信时间服务。
- “写入次数”是状态机中的事件计数。演示草稿保存在内存，不进入真实成果库或文件系统。

## 验证与下一步

定向测试覆盖能力限制、候选确认、噪音澄清、共享任务修订、播报与任务分离、旧版本拒绝、手机与桌面断线、恢复去重、过期、取消及重置。浏览器证据在忽略的 `.local/revision-02/device-simulator-qa/`，实际通过范围按操作结果续记。

与 [设备协议](DEVICES.md) 对应的真实后续工作仍包括配对身份、传输安全、硬件适配、真实采集授权、持久队列与断点恢复、可信时间和网络级重复包处理。当前纯状态机演示不证明这些底层能力可用。
