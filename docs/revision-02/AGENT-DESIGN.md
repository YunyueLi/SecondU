# Agent 身份、会话与工作交接

日期：2026-09-29。对应[本轮用户要求](BRIEF.md)。本文解释已实现的交互及其来源，不把竞品宣传画面或本地演示当作真实模型验收。

## 一条完整的使用路径

**我的 Agents 卡片地图 → 居中工牌 → 试聊或交办工作 → 持久私聊 / 群聊 → 单次批准 → 成果与版本。**

“我的 Agents”是默认入口。用户先看名字、像素头像、职责和实际参与状态，点击卡片打开居中工牌。工牌展示工作说明、来源和最近参与的任务，可以编辑、分享名片、试聊或交办工作。卡片地图与工牌采用用户明确指定的 Greenroom 岗位方案；这项选择覆盖此前以纯会话列表作为唯一入口的方案。

“对话”是并列视图。左侧保存私聊、群聊、头像、最后消息摘要和时间；选中后在中间持续交流。群聊顶部显示成员，每条助理发言保留角色身份。卡片上的试聊进入该角色已有的私聊；没有私聊才创建。会话和任务连接真实后端，示例初始化只放说明消息，不伪造已经执行的回复。

交办工作先显示目标与执行方式，再创建待开始的任务，供用户查看。直接在会话中发送则立即建立任务并运行：演示走本地演示执行器，实际运行走已配置的模型服务。任务状态、批准、成果和错误沿用应用现有实体，不再建立一份聊天专用的假状态。

## 竞品机制怎样进入实现

以下依据均复用已保存的 2026-09-29 研究材料，没有重新下载视频或重复研究。Cue、Grok Bot、Muse 的观察来自公开页面、官方图片及视频采样，未登录这些产品做端到端任务验证。

| --- | --- | --- |
| [Cue](https://cue.im/) 视频约 28–34 秒：头像、最近结果、时间组成会话列表，勾选成员建立群聊，不同角色在群里交付不同成果。 | 稳定的私聊 / 群聊历史、复合群头像、成员条、逐条发言身份、任务成果入口。 | [AgentWorkspace](../../src/agents/AgentWorkspace.tsx) 的会话侧栏、消息区、`RoomTask`；[RoomEditor](../../src/agents/AgentDialogs.tsx)。群聊 2–12 位成员，私聊恰好一位。未据宣传片推断并行调度或自动协商能力。 |

| [Meta Muse 设计页](https://introducing.muse.ai/)及[官方导览](https://www.youtube.com/watch?v=wHn0hTjvFoo)约 00:57–01:08：当前状态、活动列表、需要审阅的具体操作；约 02:15 后进入独立成果库。 | 聊天中先显示当前工作与待决定事项，活动记录可展开；产物既能从会话打开，也有独立成果页。 | `RoomTask` 的状态、活动与批准，共享 [ArtifactCard](../../src/design-system/ArtifactCard.tsx)，连接[成果预览、编辑与版本](../../src/ArtifactWorkspace.tsx)。本轮没有把 Muse 的长期 Goals、Feed、Ideas 全部实现为新入口。 |
| Muse 的长期会话组织及可回看的活动。 | 用户可以返回同一会话，看到任务与结果；继续任务时保留关联和历史依据。 | `AgentRoom`、`AgentRoomMessage` 与 `Task.roomId` 见[数据合同](../../shared/contracts.ts)，服务端保留消息、任务关联和上下文事件。Muse 研究没有出现多 Agent 名册、群聊或扫码 UI；本产品这些交互的依据是 Cue / Grok 与用户要求。 |

Cue 群聊宣传图中存在 Tokyo 请求与 Kyoto 成果不一致，因此只采用其角色与成果表达，没有将画面当作协作质量的验证。Muse 权限演示中出现过旧产品名称；Grok 视频也只按关键章节采样。以上来源支持设计取舍，不支持这些竞品的可靠性、性能或安全性结论。

## Greenroom 的复用范围

只读核对了 Greenroom 本地项目的 `app-v2/src/lib/role-avatar.tsx`、`avatar-tone.ts`、`screens/atlas-flow.tsx` 中的 `RoleBadge` 和对应工牌样式。采用的是：

- 使用确定种子在本地生成像素头像；同一个角色在地图、列表、聊天和工牌中保持同一身份。
- 地图卡片负责浏览与选择；居中工牌集中呈现身份、职责和动作，避免反复切页。
- 大小不同的头像共用一份生成结果，不依赖头像服务器。

本产品以稳定 Agent ID 为种子，改名不换脸；Greenroom 原方案以岗位种子生成。没有复制岗位知识条目、私人资料、人口属性权重或 Greenroom 的绿色视觉主题。组件和布局在本仓库中重新组合，控制组件继续直接使用官方 Apps SDK UI。

已生成的 `public/art/companions.png` 按用户要求保留备用，当前头像组件不引用该图集。

## 接口与状态约束

| 用户动作 | 实现与真实效果 |
| --- | --- |
| 创建 / 修改助理 | `POST /api/agents`、`PUT /api/agents/:id`。名称、职责、工作说明是持久实体。 |
| 创建 / 修改会话 | `POST /api/agent-rooms`、`PUT /api/agent-rooms/:id`。私聊 / 群聊、名称、成员与执行方式保存在后端。有在途任务时后端拒绝更换成员或模式。 |
| 发送消息 | `POST /api/agent-rooms/:id/messages` 创建真实任务并运行，返回 `{room, task}`。任务消息按消息 ID 去重同步到会话；角色发言保留 `agentId`。 |
| 交办工作 / 转为任务 | `POST /api/agent-rooms/:id/tasks`，`run:false`。先建立 queued 任务并打开任务页，由用户开始。 |
| 批准、拒绝、停止、继续 | 复用任务的 `/approval`、`/cancel`、`/run`、`/message` 接口。等待补充或中断后发消息会继续同一任务，不悄悄创建第二份任务。 |
| 打开成果 | 会话内成果卡指向真实成果 ID，进入现有预览、编辑与版本流程。历史成果不会被聊天展示覆盖。 |
| 进入指定会话 | `#agents/<roomId>` 与 `initialRoomId` 同步。内部切换会话也更新地址，可从全局侧栏返回指定会话。 |

后端将最近最多 30 条消息、总计约 16,000 字符作为新任务的会话背景快照；上下文存在明确上限，不宣称拥有无限会话记忆。后续成员变化不会改写已建立任务的成员与会话背景。

个人背景勾选按房间分别保存到当前浏览器会话，不会从 A 会话泄漏成 B 会话的选择。显式清空保留为空；未设置的房间默认使用已确认认识。下一次创建任务才提交所选 ID。已开始、待批准、等待补充或中断的任务中，背景面板只读显示最近一次 `context` 事件的事实文本、状态、版本与来源数。

继续旧任务沿用原来的事实 ID 集合，但执行器会在新一轮读取这些事实当时的版本，并追加新的 `context` 事件；旧事件保留。这里不能声称继续时永久使用最早文本，也不能用当前资料列表冒充历史依据。

## 头像依赖及许可证

| 包 | 固定版本 | 已核读许可证 |
| --- | --- | --- |
| `@dicebear/core` | `9.4.3` | MIT，版权人为 Florian Körner，2024。 |
| `@dicebear/pixel-art` | `9.4.2` | 非设计代码为 MIT；Pixel Art 设计为 CC0 1.0。包内 `LICENSE` 分别列出两种适用范围。 |

依赖版本写入 [package.json](../../package.json) 和锁文件。`AgentAvatar` 调用 `createAvatar(style, {seed: agent.id, size: 80, radius: 0, backgroundColor: []}).toDataUri()`，结果按风格与 ID 缓存，在应用内生成 SVG data URI，无远程图片服务请求。默认只加载 Pixel Art；其余九种风格从各自的本地包按需加载，没有加载整个 collection。

许可证一手入口为安装包内的 `node_modules/@dicebear/core/LICENSE` 与 `node_modules/@dicebear/pixel-art/LICENSE`；后者指向 [Pixel Art 原始设计](https://www.figma.com/community/file/1198754108850888330)及 [CC0 1.0](https://creativecommons.org/publicdomain/zero/1.0/)。分发时应保留包内 MIT 版权与许可文本。本文记录当前安装包的核读结果，没有重新联网查询。

后续按用户明确要求扩展到 Greenroom 的全部 10 种风格，并支持 PNG / JPEG / WebP 本地上传。所有风格包固定为 9.4.2；Micah、Adventurer 的设计为 CC BY 4.0，Avataaars、Bottts 为原作品的个人与商业使用许可，其余设计为 CC0。完整署名与许可见 [AVATAR-LICENSES.md](../../src/agents/AVATAR-LICENSES.md)，不能将所有风格概括为 CC0。上传图片在本机 `avatars` 目录保存，限制 3 MB，校验格式和文件签名，不接受任意客户端文件路径。

同轮界面反馈后，目录收敛为紧凑人员名片：头像与姓名 / 一行职责同排，只保留实际最近工作状态与单个聊天按钮；新建入口固定在顶栏，取消末尾大新增卡和每卡重复动作栏。完整职责、编辑、试聊与交办放入居中工牌。每位 Agent 可在编辑器中继承默认模型或绑定已保存连接；群聊展示各成员绑定。扫码入口在目录顶栏、对话列表顶栏与菜单中均可见。

## 完成范围和验收边界

已实现卡片地图、居中工牌、新建、扫码图片导入、编辑、试聊、私聊 / 群聊、会话成员、消息持久化、任务衔接、单次批准、停止、续跑与成果入口。错误由真实接口返回；缺少模型配置时明确等待，不显示伪造成功。多角色执行仍是同一任务下的顺序角色轮次，不宣称独立自治群体或并行调度。

本地演示使用确定的本地执行流程，不调用语言模型；用户批准后可以写出真实本地文件。“实际运行”表示任务在本机执行、模型请求交给用户配置的服务，不代表模型权重运行在本机。没有真实 BYOK 密钥的端到端调用证据，不宣称 DeepSeek 等真实模型、群聊推理质量或工具成功率已验收。

本轮没有接入商户服务、真实社交账号、电话、邮箱、支付、手机 / 眼镜硬件或 Jev；扫码是应用名片的本地图片识别。角色来源不授予执行权限。自动化和认知属于既有独立功能，不因为出现在角色附近就变成每位角色的独立电脑、独立数据库或独立安全边界。

本轮 `npx tsc --noEmit` 已通过。聊天输入区已按主界面规则统一为外层圆角、细边框与轻阴影，移除内层 Textarea 的重复焦点轮廓；“查看最新消息”的显式滚动遵循应用和系统减少动态效果设置，发送键遵循外观设置。上述是代码与类型检查结论，最终外观、键盘和完整操作流仍以主代理实际浏览器 / 原生验收记录为准。

上一版已验收的本地写入、编辑、恢复及真实 Codex 离线握手边界见 [ACCEPTANCE.md](../ACCEPTANCE.md)。不能把上一版测试结果直接当成本轮新会话 UI 已验收。本轮仅使用虚构示例，未迁移私人数字分身数据或向外发送消息。
