# 专家库与头像风格

记录日期：2026-09-29；2026-09-30 更新见下节。当前属于第二轮未提交工作树的实现；本页区分角色预设、真实运行能力和验收证据。

## 参考口径

腾讯云 WorkBuddy 产品页宣称提供 **100+ 领域专家**和 **7 万+ Skills**。这两项不能相加，Skills 数量也不能当作专家数量。专家中心文档把专家、专家团队、技能及实际工具连接分开：专家提供角色与工作方法；技能提供可复用执行能力；团队组织多个角色；外部工具仍需连接。[产品页](https://cloud.tencent.com/product/workbuddy)、[专家中心](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Expert-Center)、[技能市场](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Skills-Market)。

开放平台的专家文档列出 15 个行业分类；专家中心提供发现、查看能力和示例、添加到自己的专家列表、进入对话的路径。Claw／随身助理文档描述远程控制与通信入口，属于另一层产品能力。[开放平台专家文档](https://open.workbuddy.cn/docs/expert)、[随身助理文档](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Assistant)。

以上为当日读取官方网页后的记录，没有登录或亲手验证 WorkBuddy 应用，也没有逐项清点其全部专家或技能。可读正文、HTML、获取时间和 URL 保存在忽略的本机 `.local/revision-02/workbuddy-research/`。不将官网声明当作本产品能力。

## 本轮实现

初版 6 个模板扩为 **108 个职责预设，12 类，每类 9 个**。分类为工作协作、工程开发、数据分析、研究、学习、内容创作、产品设计、职业发展、商业运营、生活安排、人际与家庭、个人项目。每项都有独立职责、场景、个性化输入问题和能力边界；内容由本项目编写，没有复制竞品提示词。

这只是角色预设的数量对照，**不代表拥有 WorkBuddy 的工具、服务连接或实际执行能力**。例如旅行助理整理行程备选，不声称能自动订票；家庭预算助理整理用户提供的数据，不执行付款；植物养护助理根据用户提供的种类和环境制定观察计划，不冒充现场识别。

首屏展示 8 个入口，优先匹配已确认背景、当前目标及个人介绍；不足时补入常用场景，并明确标识。完整库使用搜索、分类和每页 18 项浏览，不一次展示 108 张卡片。无证据时不写“为你推荐”，候选认知不参与推荐；英文词使用整词匹配，并排除明确否定语句。

预览中可更名、选择工作重点、回答一个可选问题，再通过真实 API 创建助理。选定重点与用户主动填写的回答进入保存的工作说明；推荐所依据的个人资料不自动复制到说明或共享名片。个性化输入旁明确说明主动填写的内容会随名片分享。添加本身不启动任务，运行时仍使用实际连接、授权和任务上下文。

批量头像风格会作为当前空间的默认值与记录更新一起写入。自己创建、从专家库添加和扫码创建均继承它；上传头像默认保留，用户仍可单独指定其他风格。旧空间没有该设置但生成头像已经统一时，沿用已有风格。未统一的旧空间使用像素默认值，不擅自修改已有头像。

## 实现入口与验证

- `src/agents/expertCatalogue.ts`：新增领域模板数据；`expertTemplates.ts`：原有模板、推荐、筛选和创建草稿。
- `src/agents/ExpertLibrary.tsx`：推荐、分类、搜索、分页和预览确认；`experts.css`：专用排版。
- `server/avatars.mjs`：默认风格与原子批量更新；`server/domain.mjs`：新建助理继承；`AgentDialogs.tsx`：个人覆盖的显式选择。
- 推荐与风格共 15 项定向测试通过，包含否定与整词匹配、候选不参与、无证据不个性化、背景不进入名片、真实配置生效、原子回滚、上传保留、新建三条路径与重启继承。测试不逐字镜像 108 项模板。

原有 6 项版本的专家创建、头像批量修改、普通来源二维码创建与工牌来源显示已有浏览器证据，见本机 `.local/revision-02/final-qa/AGENT-UI-QA.md`。108 项扩展后，在独立示例空间搜索“摄影”，实际新增“摄影项目验收”，工牌背面显示保存的个性化回答；批量设置手绘线条后，新专家与该空间其余 8 位助理均继承相同风格。见同目录 `experts-108-search.png`、`experts-108-created-instructions.png` 与 `avatar-default-inheritance.json`。真实付费模型与专家效果未验收。


## 2026-09-30：SecondU 本人工牌与专家浏览

用户提供三张 Kimi Agent Swarm 的实际界面截图后，本次发现页收敛为左侧紧凑专家列表、右侧单张立体挂绳工牌、底部成员及前后切换。分类位于列表顶部，名称、职责、浏览序号同步更新；列表独立滚动，键盘方向键与 Home/End 可选专家。展示的是角色预览，没有伪造分配任务、执行中或已完成状态。资料预览与已保存 Agent 复用同一 `AgentBadgeStage`，保留工牌正反面和指针轻微倾斜。

当前目录为 **18 类、124 个独立职责预设**：产品设计、技术工程、游戏空间、数据智能、营销增长、内容创作、销售商务、金融投资、运营人力、项目质量、法务安全、行业顾问、全球发展、教育学习、日常生活、健康照护、出行探索、人际关系。沿用已有职责的稳定 ID，参考已保存的 WorkBuddy 官方分类覆盖，补充个人工作与生活领域；全部职责、提问和边界仍由本项目编写，不暗示已经接通外部工具。旧版每页 18 项分页已移除，当前以可滚动目录浏览完整结果。无个人匹配证据时显示“常用”；推荐／常用与全部是浏览方式，独立于领域筛选。

“我的 Agent”第一位固定为 **SecondU**，用 `hither` 兼容身份关联当前用户，专属紫色工牌标识“代表你”。该卡是主数字分身的视图，不会在 `agents` 中写第二个角色。开始对话进入主输入区，个人编辑进入个人画像，模型进入真实模型设置。其余角色继续按需添加。旧示例角色只对精确旧 ID 与默认名称显示专业名称，不修改自定义姓名和历史记录。专家模板中的“伙伴／搭档”改为明确专业职责；既有旧说明仍被识别为已添加，避免名称调整导致重复添加。

用户随后要求两个页面采用相同结构，替代“我的 Agent”的卡片网格：当前两页均为左侧紧凑目录、右侧单张共享工牌。领域入口紧邻“发现专家”，用含图标的分组弹层展示；搜索与领域取交集。“我的 Agent”按实际名称、职责和说明检索，支持最近使用、最近添加与名称排序，没有虚构工作时间；没有模板来源的自定义角色保留独立分类。SecondU 固定入口不因专业领域筛选消失。宽窗口工具栏保持一行，390px 下分为两行。

工牌使用固定头像、名称、两行职责和归属区域。相同窗口内从一行职责切换到两行职责，头像、名称和底部位置保持一致；首次出现仅轻摆一次，减少动态效果偏好下停用。新增可选英文名独立保存，不从拼音或角色名称推断用户英文名。

工牌的“身份与权限”已接入真实本机资源模块，由其管理账号绑定、能力检查与每项操作规则；弹窗标题与关闭按钮固定，长列表在内容区滚动。分享按钮仍明确标为“分享角色说明”，提供现有可用的角色说明二维码。它不代表真人专业分身已发布，也不暴露个人知识库或生成公共可调用链接。

导航的个人画像、生活近况、聊天记录、时间轴、关系图谱与资料来源各有一致尺寸的 SDK 图标。Agents 标签、分类、列表标题与说明统一正常文字对比度和 12–14px 阅读层级。首页输入区按用户最后提供的参考保留上下两层：上方白色输入区带轻边线与柔和阴影，下方为连续灰色工具托盘。托盘左右内收，项目、连接器与数字分身模式处于同一层，长文本展开后保持两层关系；已有普通对话和群聊继续使用文本在上、操作在下的布局。
