# 从现实来源创建助理

更新：2026-09-29。实现与本地针对性验证完成；浏览器实屏验收由主任务统一执行。

## 参考与采用边界

本轮复用了已归档的 [Manus 2.0 官方介绍](https://manus.im/zh-cn/blog/introducing-manus-2-0)，未重抓竞品素材。官方说明 Cue 可通过餐厅二维码进入日常服务。归档演示约 02:20–02:30 显示带来源域名的店铺 Agent 与持续会话，约 02:30–02:38 显示结构化订单审批。时间点来自既有采样记录，允许约 1 秒误差；并非对 Manus 的亲手验证。

SecondU 采用的是“现实场景入口 → 可检查的来源 → 用户定义的持久助理”这段交互。扫码并不证明网站身份，也不意味着商户已接入，更不授予服务或付款权限。

## 已实现

- `src/agents/qrImport.ts`：图片二维码和粘贴文本使用同一解析器。SecondU 名片或 JSON 进入已有角色预览；普通 HTTP(S) 链接进入来源预览。
- `src/agents/AgentDialogs.tsx` 的 `AgentCardDialog`：本机读取二维码图片；来源预览显示规范化域名和完整链接，用户填写名字、职责及工作说明后才创建。说明可关联现实物品或场所，页面明确这是用户自行创建的助理。
- 创建实际调用 `POST /api/agents`，持久化 `sourceUrl`。该过程不创建会话或任务、不改模型绑定、不读取网页。
- 分享名片保留 `sourceUrl`，只导出名字、职责、工作说明及该链接。会话、个人认知、模型设置与权限不进入名片；用户写入工作说明本身的内容仍会随名片分享。
- `shared/agent-source.mjs`：前后端共用 URL 校验；拒绝非 HTTP(S)、含用户名或密码、无效主机、嵌入控制字符、反斜线及过长链接。`server/domain.mjs` 同样校验直接 API 请求。
- 创建成功但刷新列表失败时保留已创建 ID；重试只刷新，不重复创建。图片解码有卸载/读取序列保护。

## 验证

`node --test tests/qr-source-import.test.mjs`：5 项通过、0 跳过。

覆盖真实 QR 矩阵生成后像素解码到来源预览、SecondU 名片兼容、来源分享往返、中文域名规范化、无 QR 图错误、用户名/密码与 javascript 链接拒绝。实际临时 HTTP 服务验证创建持久化、不自动产生任务或会话、不修改模型连接、错误创建/修改保持原记录。测试使用独立临时数据目录，不触碰个人数据。

`npx tsc --noEmit`：通过。

## 仍然没有实现的能力

- 不使用摄像头实时扫码；当前入口是图片或粘贴链接。
- `sourceUrl` 是溯源信息，不代表已经读取网页或掌握网站内容。需要用户在对话中提供资料；本轮没有网页抓取、菜单解析或网站工具接入。
- 没有商户身份认证、库存/排队/订单 API、付款或外部授权能力，也不把第三方网站指令自动转换成权限。
- 本轮没有实际调用 BYOK 模型，不声称已完成模型端或商户端验收。
