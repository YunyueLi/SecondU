# 2026-10-24 光效、动效与产品界面研究

**2026-10-25 修正：** 输入框参考被先后误读为 SVG 拖尾和 conic 细环，两者均已被用户否定。重新核对原片后，当前实施目标是稳定边框、周围及内侧弥散柔光，采用用户明确要求的轻微呼吸；不再以光头沿边绕圈为目标。颜色共用外观中唯一的强调色选择，仅实际运行中的任务启用。原片可证实光区迁移和表面染色，但约 3.4 秒的相关镜头不足以证明呼吸周期。下面保留此前研究与误判过程，并明确区分事实、历史实现和新的实施目标。

本文记录研究、取舍、当前源码与验收要求。当前规范见 [DESIGN](../DESIGN.md)，实现进展见 [DEVELOPMENT](../DEVELOPMENT.md) 和 [ITERATION](../ITERATION.md)。这里的“已实现”指本机工作版本，不能据此推定已发布、已完成全产品验收或获得用户最终接受。

## 1. 证据范围与本机材料

- 原有 280 个研究文件保持逐文件校验值不变，包含视频、267 张逐秒帧图、画面文字、5 张联系表和 3 组动作序列。

## 3. 七类相近光效的区别

分类依据是“光在哪里、什么触发它、它向使用者表达什么”，而非组件名称中是否含有 glow、shine 或 shimmer。

| 家族 | 视觉与机制 | 合适用途 | 禁用或需额外处理的情形 | 当前采用 |
| --- | --- | --- | --- | --- |
| **沿边光束** Border beam | 独立光头及尾迹沿闭合轮廓运动；路径与角度驱动具有不同速度特征。 | 用途明确的局部引导或研究样本，须另行说明状态含义。 | 把视频中的任何“高光”都归入此类；等待、失败或未知状态仍暗示执行。 | 不再作为当前输入框方向。原 SVG 拖尾与 conic 细环均已否定；当前目标是稳定边框周围及内侧的弥散柔光，见第 4 节。 |
| **整圈光晕** Perimeter aura | 整条边缘持续可见，外围模糊形成柔光；可叠加清晰边线。 | 单个重点展示对象、品牌材质探索。 | 大面积表单、密集列表、所有选中项同时发光；柔光侵入文字或相邻控件。 | 目录中可暂停的缓慢呼吸样本。 |
| **渐变轮廓** Gradient border | 多色沿边界分布，通常用背景和遮罩保留边框，也可用 SVG；静态即可成立。 | 辨识某种展示材质或局部强调。 | 未配文字时承载成功、错误或权限含义；把旋转渐变误称为沿矩形匀速移动。 | 目录中的静态研究样本。 |
| **指针聚光** Pointer spotlight | 由指针位置更新径向亮区，光落在表面或局部边缘。 | 桌面上的可交互区域探索，配有独立键盘反馈。 | 仅悬停才能发现关键内容；触屏丢失入口；指针移动逐帧更新整页 React 状态。 | 目录局部光点，半径随容器限制在 28–68px，离开后淡出，正文和边界始终可用。 |
| **内容占位扫光** Skeleton shimmer | 按预期内容结构绘制占位形状，让亮带扫过占位区。 | 首次加载且能预知大致布局的异步内容。 | 已有内容的刷新反复清空成骨架；空数据、错误和权限拒绝仍无限扫光；用它表达执行进度。 | 目录包含加载、完成正文和重新加载切换；业务采用须对应真实加载状态。 |
| **镜面扫光** Specular sweep | 一条线性亮带划过表面或字形，模拟材质反射。 | 一次悬停或聚焦反馈、有限的品牌展示。 | 每张卡片自动无限循环、覆盖小字、暗示后台活动；强光闪烁。 | 目录样本，悬停或聚焦时单次播放。 |
| **轮廓显现** Contour reveal | 接近或聚焦时局部轮廓显现，离开后减弱；可由距离、角度和遮罩控制。 | 辅助辨识相邻可交互表面。 | 代替 focus-visible、隐藏必要分隔、触屏没有替代反馈。 | 目录样本，独立保留键盘焦点。 |

### 公开实现中容易混淆的细节

[MagicUI Border Beam](https://magicui.design/r/border-beam.json)用运动路径及 `offsetDistance` 驱动局部光束；[Shine Border](https://magicui.design/r/shine-border.json)使用放大的径向渐变背景往返移动，再用遮罩保留边框。这两者的空间行为不同。后者源码有减少动态效果相关的 `motion-safe` 限定，不能由此推定整个组件库的每项示例都具备相同处理。

[Neon Gradient Card](https://magicui.design/r/neon-gradient-card.json)组合清晰轮廓与模糊光晕，示例模糊量与宽度有关；直接用于宽面板会扩大重绘区域。[Magic Card](https://magicui.design/r/magic-card.json)的指针聚光和 [Glare Hover](https://magicui.design/r/glare-hover.json)的线性亮带也承担不同的交互含义。[Shimmer Button](https://magicui.design/r/shimmer-button.json)虽然名称含 shimmer，其实现包含边缘光点的旋转与横移，不能把它归为加载骨架。[Animated Shiny Text](https://magicui.design/r/animated-shiny-text.json)是裁切到字形的渐变移动；[Backlight](https://magicui.design/r/backlight.json)则使用 SVG 滤镜形成背光。

[Aceternity Glowing Effect](https://ui.aceternity.com/registry/glowing-effect.json)按指针方向与接近范围控制锥形遮罩，含 inactive zone 与 proximity 概念；它的[说明页](https://ui.aceternity.com/components/glowing-effect)自述为另一网站风格的复现，不能标成该网站的官方源码。[Card Spotlight](https://ui.aceternity.com/registry/card-spotlight.json)还引入 Canvas Reveal 与 Three.js 相关依赖，成本边界超出一层 CSS 径向渐变。[Hover Border Gradient](https://ui.aceternity.com/registry/hover-border-gradient.json)在未悬停时也会轮换方向；[Glare Card](https://ui.aceternity.com/registry/glare-card.json)组合纹理、混色、亮区与倾斜，属于材质表现。

因此，本轮按机制自行实现小范围样本，没有把上述展示代码整套接入产品。后续若实质复制源码，必须按对应版本复核依赖和许可。[MagicUI 的 MIT 许可](https://github.com/magicuidesign/magicui/blob/main/LICENSE.md)需要保留版权与许可文本；[Aceternity 官网条款](https://ui.aceternity.com/terms)带有 Pro 产品语境，本轮未确认覆盖全站全部组件的统一 MIT 授权。

## 4. 对输入框光效的两次误判与重新复核

### 2026-10-25 原片复核与当前实施目标

本轮从 `source-0.mp4` 的 25.000 秒起按 0.2 秒采样，实际看完 20 帧；另查看 26.600—26.900 秒的连续 10 帧，以及对应画面字幕。输入框可比镜头约为 25.4—28.6 秒，前后分别为赛事画面和手机。新抽帧以视频 PTS 为准，原始逐秒帧和 OCR 只辅助核对。材料、精确采样、联系表及不确定性已保存于输入框复核归档（本机保存，不随仓库分发）和离线查看页（本机保存，不随仓库分发）。

| 原片时段 | 可证实的画面 |
| --- | --- |
| 25.4—26.4 秒 | 中性亮边从左上移向上边右段及右侧；表面、圆角和控件几何保持不动。 |
| 26.6—26.9 秒 | 紫蓝右边和右下柔光，与底边中右红橙区域同时存在；连续相邻帧显示宽色区渐变，色光向表面内侧扩散。 |
| 27.0—28.0 秒 | 底部多段颜色与左下青绿共存，随后左边、左上和上边左段渐亮；变化具有空间迁移，并非只有整体统一闪烁。 |
| 28.2—28.6 秒 | 顶部出现长段青蓝、红橙混色，右上有较淡过渡，随后切镜。 |

该示例更适合描述为边缘材质高光叠加弥散色光：常同时覆盖长边、圆角和相邻边，没有可证的孤立尖亮光头带线状长尾。色光主要在输入框内侧可见，外部黑背景上的扩散较弱；不能据此认定它只用外部阴影，也不能排除黑背景隐藏了暗影。边缘几何稳定，但亮边的亮度和位置仍变化。

画面字幕中的“流动的高光”及 Siri 类比是观感描述，没有给出 Border Beam 组件、CSS、shader 或运动路径。此前先选择沿边光束类别，再围绕路径、尾迹和细芯寻找实现，导致研究被实现名牵引。SVG 阶梯改成连续 conic 细环只改变技术，仍遗漏了宽柔边和内侧表面染色。两次方案均已被用户否定。

当前实现采用稳定中性表面和基础边框，加上周围及内侧低透明弥散色区，以三片区域缓慢交替呼吸。三片色区和轻微呼吸来自产品选择与用户明确要求，**不是原片已证的光源数量或周期**。颜色跟随唯一的全局强调色，仍只在真实 running 时启用；等待、停止中、失败、完成和未知状态关闭活动效果。已按开发记录检查浅色桌面、深色 320px、减少动态、关闭及任务完成后的停止；实体手机、完整辅助技术与性能结论仍需独立验证。

该片段没有证明具体制作技术、完整循环、呼吸幅度、沿路径匀速、浅色效果或真实产品运行状态；640×360 压缩帧也不能直接给出 CSS 像素参数。后续验收应观察完整明暗周期和材料观感，不再以绕行一圈作为通过条件。

### 已替代的 SVG 方案

最初采用 SVG 是为了直接表达沿圆角路径的距离，避免把中心角度误当成矩形周长。随后扩展的版本用 24 层同头描边叠加长尾，最长覆盖 36 个归一化路径单位，并叠加亮核、细芯与两层模糊。用户在真实画面中指出它呈现分段、粗蓝带，与参考下半部输入框的细中性高光和局部柔边不符。该方案及更早的摘要小徽标接入均已替代；这里保留原理和失败原因，不将它们作为当前规范。

旧版每条移动描边设置 `pathLength={100}`，用数值 `strokeDasharray` 表示一段实线与剩余空隙，改变 `stroke-dashoffset` 后每圈移动 100 个归一化路径单位。拖尾层长度和偏移初值对应，使各层亮头对齐。这里的 `100` 是路径校准单位，**不是 `100%`**；描边百分比依据视口的归一化对角线计算，不能直接当作周长百分比。[SVG pathLength](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Attribute/pathLength)、[stroke-dasharray](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/stroke-dasharray)

对于宽高为 `w`、`h`、圆角半径为 `r` 的有效矩形轮廓，周长为 `2(w + h − 4r) + 2πr`。旧版固定每圈 3.6 秒，因而同一尺寸内按归一化路径推进，但宽面板的像素速度高于短状态条。这个几何结论仍成立；它不能消除多层叠加产生的阶梯、粗带和视觉重量问题，也不能证明旧版视觉达标。

### 随后尝试的 conic 细环（已否定）

替代 SVG 的一版[组件](../../src/design-system/ActivityEdge.tsx)曾以 `@property` 将 `--activity-edge-angle` 注册为 `<angle>`，在 0°—360° 之间按 3.6 秒连续插值；`conic-gradient` 提供尾迹透明度与局部柔光，固定圆角双层遮罩只保留细环。变化的是渐变角度，容器和圆角不旋转；运行环境缺少原生注册属性能力时保留静态轮廓。这些技术描述保留为历史，不再代表当前输入框规范。[@property](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@property)、[mask-composite](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/mask-composite)

旧细芯使用明暗主题文字色，柔和／鲜明分别为 .75px／1px 宽、.45／.65 整体透明度；渐隐尾迹由同一渐变生成。前端柔光层的透明度为 .16／.22，材质环为 1.5px、模糊 .8px，宿主外侧裁切范围最多 3px。该约束过于集中在细线和局部光头，未保留参考向内部扩散的宽色光；这些旧参数不应继续作为新方案的默认值。

### 保留的状态与外观契约

组件默认 inactive；`active=false` 时立即移除，没有延迟退出计时器。业务省略 `intensity` 时继承关闭／柔和／鲜明（`off/subtle/expressive`）设置，新配置默认鲜明；旧 `quiet` 仅作 `subtle` 的兼容别名。业务颜色读取实际 `--hither-accent`，与唯一强调色选择共用石墨、蓝、紫、绿、青绿、暖金、多彩七个预设及自定义 `#RRGGBB`。多彩通过 `html[data-accent=spectrum]` 只改变局部柔光。旧 `activityPalette` 已退出业务外观偏好，也不再依赖 `data-activity-palette`。[共享外观定义](../../shared/appearance-options.mjs)

[外观设置](../../src/AppearanceSettings.tsx)已删除独立流光配色行、大块流光预览和永久“已保存”成功标记，仍保留自动保存、真实错误与未保存保护。组件的显式 `palette` 只用于目录研究，覆盖样本对应颜色，不写持久设置；显式样本强度也不能覆盖系统或产品的减少动态效果。颜色不表达任务结果。

### 保留的几何与浏览器边界

`conic-gradient()` 按中心周围的角度分配颜色。圆形轮廓上角度与弧长成正比，长方形上的匀速角度变化则不对应四条边上的匀速路程。此前选择连续渐变消除叠层阶梯与粗带，却保留了沿边运动这一未经充分验证的目标。固定遮罩只保持形状，不能改变角度关系，也不能据此称作沿周长匀速。这个几何说明仍成立，但不构成新柔光方向的采用理由。[MDN：conic-gradient](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/gradient/conic-gradient)

若后续场景必须控制沿路径的速度，应重新评估路径距离方案及其连续尾迹表现。CSS Motion Path 的 `offset-distance` 可以表达沿路径位置，具体 `offset-path` 语法需按目标浏览器核验。[Motion Path 规范](https://www.w3.org/TR/motion-1/)、[MDN：offset-path](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/offset-path)

目录默认复用 `ComposerSurface`，在局部浅色和深色区域同步展示；窄容器堆叠，另可选择宽面板和紧凑状态条比较几何。业务和目录输入框均从 `--composer-activity-radius` 读取圆角，随紧凑、展开、首页与手机断点改变。这里复用真实组合，但目录按钮只切换本地预览状态，不发送任务。局部主题与显式配色不会更改用户外观偏好。[目录实现](../../src/catalogue/MotionExamples.tsx)、[共享输入框](../../src/composer/ComposerSurface.tsx)

指针聚光只修改样本局部 CSS 变量，使用 `requestAnimationFrame` 合并每帧更新，不通过 React 状态重绘整页。光点位置限制在容器范围，半径随宽高缩放并限制在 28–68px；指针离开或取消时取消待执行帧并淡出。键盘聚焦且没有指针激活时，光点居中并静止；独立焦点环继续可见。触屏保留正文与基础边界，不依赖悬停。[局部几何](../../src/catalogue/light-study-pointer.mjs)、[材质样式](../../src/catalogue/motion-examples.css)

其他技术约束：`border-image` 不会因 `border-radius` 自动获得相同圆角；遮罩合成需要检查实际浏览器表现；注册 `@property` 只解决类型及插值的一部分问题，不等同于合成线程或 GPU 加速保证。[border-image](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/border-image)、[mask-composite](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/mask-composite)、[@property](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@property)

## 6. 可访问性与生命周期

持续动效必须能被减弱，状态仍应完整可读。当前实现同时响应系统 `prefers-reduced-motion` 与产品 `data-motion="reduced"`，任一生效即停止流动；启用中的装饰保留静态轮廓，外观选关闭时继续隐藏装饰。显式样本强度不覆盖减少动态效果。强制颜色模式使用系统色边界，避免依赖渐变或阴影。装饰层从辅助技术中隐藏，可见文字独立提供状态。真实百分比未知时不填写虚构的 `aria-valuenow`，含交互的整张卡片也不应仅为添加进度语义而改成 progressbar。[减少动态效果](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion)、[强制颜色](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/forced-colors)、[progressbar 语义](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Reference/Roles/progressbar_role)

[可见性管理](../../src/design-system/activity-edge-visibility.ts)初始保持暂停，收到交叉观察结果后才运行；元素离屏、文档隐藏或局部预览暂停时停止动画播放，返回后继续原相位。卸载时清理观察器和监听器。关闭动画不会停止业务任务，业务任务也不能从动画是否可见推断状态。[Page Visibility](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)

验收须区分以下要求：

- [WCAG 2.2.2 Pause, Stop, Hide](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html)是 A 级。自动开始、超过五秒、与其他内容并行等适用条件需要具体判断，不能一概把 loading 排除在外。
- [WCAG 2.3.3 Animation from Interactions](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html)是 AAA 级，不能写成 AA；减少非必要交互动效仍是产品采用的原则。
- [WCAG 4.1.3 Status Messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)是 AA 级。状态变化需要可程序识别且不抢夺焦点；逐秒计时和光束相位不应反复播报。
- 焦点环、选择态、错误态和触摸入口各自完整存在。指针聚光不能替代键盘反馈，低强度边缘装饰也不能作为文字或控件对比度达标的依据。

这些规则与源码覆盖只能说明实现方向；屏幕阅读器、键盘连续操作、系统设置变化和目标浏览器实测仍需分别留证，不能由静态页面或单元测试替代。

## 7. 性能判断与验证方法

旧 conic 方案由注册角度属性驱动，没有逐帧 React 更新，但渐变角度变化会重绘。新的弥散柔光和呼吸需要重新检查渲染成本；即使主要动画改变透明度，渐变、阴影、遮罩和模糊的实际合成与绘制仍取决于实现和浏览器。不能预先称为零绘制、纯合成线程或 GPU 加速。优先评估 transform／opacity 是否适合目标效果，限制模糊半径与绘制面积，不为大量节点永久设置 `will-change`。[web.dev 动画性能指导](https://web.dev/articles/animations-guide)

WebGL 适合确有空间、粒子或着色需求的展示；简单状态轮廓不应因为外部样例使用了 Three.js 就引入整个渲染栈。需要 Canvas／WebGL 时，应额外验证像素密度、显存、资源释放、上下文丢失与低性能设备行为。[WebGL best practices](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_best_practices)

实际记录至少包含同一页面的静态基线与开启动效后对照，并覆盖：真实助理和 Agent 输入框、目录双主题输入框、状态条、宽面板和多个可见实例；明暗主题；前台、后台和离屏；缩放或布局改变；系统减少动态效果。新方案计划使用三片弥散色区，层数与使用透明度都不能直接证明性能提升。建议用 1、8、24 个实例覆盖正常与压力场景，记录设备、刷新率、帧时间和绘制区域；压力数量不是生产设计目标。检查长任务、掉帧和滚动响应，不能以一个性能分数代替交互判断，也不能仅根据 CSS 属性推定某个固定帧率。

现阶段没有在本文给出帧率、CPU、GPU 或电耗提升的量化结论。完整明暗周期的录像、退出状态和性能轨迹属于后续具体场景验收内容。

## 10. 其他主源及采用理由

- [Vercel Geist Skeleton](https://vercel.com/geist/skeleton)：已知布局的异步占位，与 Spinner、Progress 和空态分开。
- [Vercel Web Interface Guidelines](https://vercel.com/design/guidelines)：可中断动作、减少动态效果、焦点及多种状态提示；品牌偏好不直接改写为通用硬规则。
- [Fluent 2 Motion](https://fluent2.microsoft.design/motion)：动效服务功能、保持自然与一致，并控制注意力范围。
- [Fluent 2 iOS Shimmer](https://fluent2.microsoft.design/components/ios/core/shimmer/usage)：加载占位与 Reduce Motion 的产品处理；iOS 建议按平台语境使用。
- [Material 3 MotionScheme](https://developer.android.com/reference/kotlin/androidx/compose/material3/MotionScheme)：standard 与 expressive 的用途区分可帮助讨论日常反馈和重点表达，不直接移植 Android 时长到 Web。
- [Linear 的界面重设计记录](https://linear.app/now/how-we-redesigned-the-linear-ui)：信息层级、视觉噪声和实际环境检查；不能据此宣称其禁止某类光效。
- [Microsoft Reveal Highlight，2017](https://learn.microsoft.com/en-us/shows/windows-windows-developer-day-fall-creators-update/windev013)：轮廓显现的历史案例，不能标为当前 Fluent 2 的默认规范。
- [MDN offset-distance](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/offset-distance)：沿路径位置的定义，补充几何实现核对。
- [MagicUI Border Beam 说明](https://magicui.design/docs/components/border-beam)：组件意图与源码互相对照，示例观感不能替代实际性能和状态约束。
- [Marco 作品入口](https://marco.works/)：保留视频提及的公开入口；本轮完整抓取失败，没有用它新增未经证实的作品或署名结论。
