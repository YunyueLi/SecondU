# SecondU 产品定位与完整形态

**你的数字分身。从懂你，到为你行动。**

SecondU 是以个人数字分身为核心的智能体产品。SecondU 持续理解你的背景、经历、偏好、关系和目标，在不同任务、场景和设备之间延续这些理解。组织归拢零散多模态信息，调度合适的专家与工具，主动处理任意想法与事务，并支持协作、社交和专业服务。

用户掌握自己的资料、分身和授权范围。随着资料积累、日常使用和模型能力提升，SecondU 应当越来越准确地理解这个人，也越来越有能力提供及时、合适的帮助。数字分身提供对本人的持续理解，包括经历、价值观和长期目标；个人 Agent 将这种理解用于讨论、判断与行动。用户可以反复追问依据、补充信息和修正理解，重要选择仍由本人决定。两者共同构成产品的核心。

本文描述完整产品方向与体验目标。具体能力的已实现范围、实际验收和后续规划分别记录，不能将完整形态当作当前版本的交付声明。

## 用户为什么需要 SecondU

一个人会在不同工具里反复说明自己：申请时填写经历，写作时解释立场，做项目时补充之前的决定，安排生活时重述时间、预算和同行者的情况。很多判断已经表达过，也已有资料支持，却在下一次任务、另一个项目或另一台设备上重新开始。

SecondU 将这些个人资料、经历和判断组织成可以持续维护、按需使用的个人上下文。用户可以从“再解释一次我是谁、为什么这样想”，逐渐转向“在已有了解上，帮我把这件事做好”。它既服务于一次具体请求，也参与需要多次沟通、持续跟进和实际执行的长期事务。

我们此前确定的三项重点价值都包含在这个范围里：**减少背景信息和既有判断的重复输入；让完整的多模态上下文在设备和场景之间连续流转；将经过授权、适当脱敏的个人专业能力分发出去，支持 Agent 之间的协作、社交和交易。** 三项重点用于说明价值，不限制产品的完整范围。

## 个人认知体系

SecondU 整理个人资料、交流记录、经历、关系、作品和过往决定，形成对这个人持续更新的理解。既包含可复用的身份与经历，也包含当前在意什么、习惯怎样判断、不同情境下如何取舍，以及现实中的资源和限制。

这种理解必须保留上下文和时间。一次工作的偏好不应变成所有事情的固定标签，旧住址、旧目标和过去的关系状态也不应一直被当作现在的情况。用户能够查看、纠正和补充，重要判断能够回到原始资料。

个人上下文由本人管理，可以在不同项目、模型、专家与工具之间按需授权使用。它会成为用户长期积累的个人资产。每项任务取得与当前事情相关、被允许使用的部分；“完整管理”并不意味着把全部私人资料交给每一次调用。

## 从已有资料开始

用户可以主动导入自己整理的 `AGENTS.md`、`CLAUDE.md`、Markdown 或 JSON 摘要，在同一流程中核对背景、偏好、目标和约束，逐条修改并明确确认，然后带入一项可编辑任务。原文、初始候选和确认后的修订一起保留；只有本人发送后，才开始真实执行。导入不会执行文件中的指令，也不扫描其他应用的私有记忆库。

通信连接提供另一种入口：在应用内选择独立 OpenClaw 运行环境或已有工具，完成逐渠道授权，限定账号与会话，先预览再保存。当前向导为 13 个渠道提供授权配置，包括 QQ、企业微信、飞书 / Lark；历史消息读取仅覆盖 Slack 与 Discord，其余已列渠道支持确认后发送。平台权限和实际连接状态分别检查，微信与钉钉的当前兼容性限制见 [通信接入](COMMUNICATIONS.md)。

个人认知可以导出为带状态、版本和简短证据的 JSON 或 Markdown。它面向持续维护与按需使用，不包含模型凭据、完整聊天库或可执行权限。[记忆导入与封装](MEMORY-IMPORT.md) 和 [通信接入](COMMUNICATIONS.md) 记录具体范围。

## 个性化判断与任务执行

SecondU 将对本人的了解用于写作、研究、求职、申请、学习、创作、出行和生活安排。用户可以直接提出需求，也可以允许它在约定范围内发现值得处理的事项、提出建议并继续推进。

例如，申请材料能复用已经确认的经历，文章能参考本人采用过的表达和立场，家庭行程会考虑同行者的时间与体力。它应减少重复询问和不合适的建议，并产生可审阅、可修改、可继续使用的结果。

面对职业转换、购房定居、学校与成长、亲密关系等重大选择，SecondU 应结合已确认的经历、价值观和长期目标，协助梳理事实、比较得失、发现遗漏与不确定性。它可以帮助准备向相关人士核实的问题，并随着新信息继续讨论；不把预设偏好当成人生结论，不替本人作出选择。标准示例已将职业方向讨论放进实际任务工作区：根据中英文人物各自既有背景，展开四轮问答并保留可编辑提纲。会话由作者预先编写，未调用模型，也不把讨论意向写入长期个人事实。

执行可以发生在用户自己的电脑或接入的远程环境，通过应用和工具处理实际事务。随着能力和信任逐步建立，用户可以委托更多事情；发送、购买、身份使用和其他对外承诺，仍受具体授权约束。用户随时能够补充要求、接手或停止。

### 如何判断个性化是否有用

关键证据是一条可以复查的变化链：已有背景使本次建议作出不同取舍；本人指出理解偏差；纠正经确认后保留新版本；下一项相关任务使用新理解，不再重复旧建议。相同材料、相同任务与普通对话对照，才能判断是否减少重复解释和约束遗漏。成果编辑证明交付可以继续使用，不能单独证明个人理解的价值。

## 答复评价与个人理解纠正

每条答复的赞、踩和补充原因用于表达本次回答是否有帮助；它们作为答复评价保存，不自动写成个人事实或偏好。需要改变以后任务对本人的理解时，用户另行打开「纠正个人理解」，填写纠正内容与适用范围，保存为候选，再明确确认。

「继续修改」把当前答复引用到输入框，由用户补充要求并决定是否发送。当前不提供一键「重新生成」，避免在没有新请求与授权判断时重放可能含工具操作的整项任务。导出答复、补充反馈与个人理解纠正各有独立入口。

## 专业智能体协作

了解本人的 SecondU 是协作中心。用户可以发现、添加和委托擅长研究、写作、编程、设计或其他领域的专业智能体，也可以让它们围绕同一件事共同工作。

每个智能体可以配置适合的模型、知识、工具和执行资源，按需绑定邮箱、号码、计算机或付款权限。任务中的材料、责任和授权分别确定，工作结果汇入用户正在推进的事情。

协作的价值需要体现在实际结果里：研究找出有用依据，专业判断补足遗漏，执行完成操作，最后留下用户能够继续修改的成果。角色数量和对话轮数本身不能代表协作质量。

## 项目与长期事务管理

SecondU 将相关的对话、资料、待办、决定、文件和成果版本放在一起。用户隔几天回来，能够从上次的进度继续；已经确认的修改和取舍成为后续工作的起点。

产品支持工作项目，也支持申请、旅行、家庭安排、学习计划和个人创作等生活事务。自动化可以在约定的条件下持续整理信息、跟进变化、提醒事项和执行动作，使长期目标得到持续推进。

用户应当清楚哪些事情已经完成，哪些仍等待资料、外部回应或本人决定。一次生成回答、生成一份文件，以及现实中的事情办成，是不同的状态。

## 多设备与多模态协同

电脑、手机和眼镜是同一个 SecondU 的不同入口。个人认知、任务状态、原始输入和工作成果连续保留，设备根据当时的场景承担合适的交互。

眼镜和手机可以记录现场看到、听到的内容，也可以承担即时沟通；电脑适合复杂处理和编辑；离开电脑后，用户仍能在手机上查看、补充或确认。现场一句话、一张图，能够进入正在推进的事情，之后的修改也能够接续回去。

这要求完整地管理文字、图像、语音等资料及其来源，让原始内容、后续理解和成果版本都有连续记录。跨设备的价值要通过同一件事实际接上来体现，并逐步延伸到与现实环境持续交互的体验。

## 个人能力分发、市场与社交

用户可以把某一方面的知识、经验和专业能力，与允许使用的个人上下文一起，封装成可被调用的专业分身，通过链接、二维码或名片提供给他人或其他 Agent。

专业分身可以回答问题、接受委托、参与协作，也可以在双方愿意的情况下帮助寻找合适的人、专家与合作机会。这个网络同时服务于人与人、人与 Agent、Agent 与 Agent 的连接：本人可以亲自参与，也可以让自己的 Agent 先了解情况，再把值得继续的事情交还本人。

本人决定分身可以使用哪些资料、回答哪些问题、为谁服务，以及调用次数、费用和服务规则，并可以调整、暂停或撤回。对外分发的是明确用途下的一部分能力；个人完整资料和私人关系不会随之默认公开。

### 目录入口与当前 Dev 范围

Agents 目录的一级页签依次为「我的 Agent」「发现专家」「Agent 市场 Dev」「Agent Dating Dev」。市场与 Dating 是两个独立入口，不再合并进「Agent 网络」。四个页签占用独立导航行，分类、搜索和头像风格保留各自操作位置；常用领域适度展开，「更多」提供完整分类。头像风格保留完整文字入口，并以同一默认风格衔接我的 Agent、发现专家和市场工牌。

市场列表与服务详情直接复用既有 `AgentBadgeStage` 工牌，展示 Agent 的身份、提供方、服务范围和报价。当前支持本页内的搜索、筛选、查看服务、填写需求、选择示例资料、确认示例报价及交付验收步骤，未连接真实服务方、付款或交易网络。

Dating 提供独立的偏好设置、人物建议、左右滑动或按钮选择、撤销、兴趣列表和开场白草稿。推荐理由与 Agent 交流均来自明确标记的虚构示例；原创水彩双人插画用于表现相遇，不冒充人物照片。表达兴趣只保存在本页，没有联系他人、形成真人匹配或执行真实 Agent 初筛。两页的最新目录布局、工牌与交互仍在实际验收中，Dev 可操作不代表服务已交付或用户已接受。

### 专业服务与 A2A 交易

一个设计师可以发布懂自己作品和方法的专业分身，一个研究者可以开放某个领域的知识服务，一个商家可以提供可持续联系的预约或服务 Agent。用户的 SecondU 按需求寻找合适的对象，了解能力、价格、时间和交付方式，形成可以比较的方案。

一次委托需要从需求走到结果：说明问题与可用材料，询问或报价，核对范围和费用，确认委托，执行与阶段交付，验收和结算，最后保留可继续使用的成果与记录。参与者可以是个人分身、专业 Agent 或服务方 Agent；用户应能看懂每个参与者的身份、职责和收费对象。

A2A 交易的愿景包括付费问答、咨询、审阅、创作、研究和其他专业服务。分发能力与出售完整私人资料是两回事；专业分身只使用本人为这项服务选定的材料。付款、合同和现实交付需要独立接入与验证，前端演示不能生成真实订单或支付成功状态。

### 朋友、合作与恋爱匹配

SecondU 也可以帮助用户建立现实联系：找到一起做项目的人、能交流某个兴趣的朋友、适合互相介绍的专业伙伴，以及愿意认真认识的恋爱对象。匹配应同时考虑双方主动表达的期待、生活安排、沟通习惯和当下意愿，给出可理解的联系理由。

例如，两个人都想周末看展、时间接近，也都选择开放新的朋友介绍，双方的 Agent 可以先比较这些已开放信息，再分别询问是否愿意认识。恋爱场景中，还需要尊重双方明确的择偶范围、关系意愿和拒绝选择；没有人应在不知情时进入匹配池。双方确认之后才进入介绍或见面安排，不能由相似度分数代替本人作决定。

### 现实服务与长期关系

扫码、链接或搜索可以成为认识一个服务 Agent 的入口。用户以后能继续联系同一位服务方，延续已确认的偏好、预约和服务记录。用餐、活动、旅行、学习与本地服务都可以成为具体场景，产品不必为每个行业再造一套完整业务系统。

服务完成之后，经过确认的结果进入用户正在推进的事情；值得保留的经验才进入后续理解。服务关系和个人认知相互连接，但商家、专家或其他人的 Agent 不能因此取得用户全部背景。

## 完整形态的能力版图

个人认知是这些能力共同使用的基础。产品可以按阶段实现，但定位和界面规划要保留完整方向，不能只剩画像展示或几种聊天角色。

| 方向 | 用户能够做什么 | 产品中的位置 |
| --- | --- | --- |
| 认识与理解本人 | 汇集文字、聊天、文件、照片、语音及获准的活动，形成经历、关系、偏好、目标与当前处境 | 数字分身、资料来源、时间轴、关系图谱 |
| 工作与生活助理 | 写作、研究、申请、学习、创作、出行、家庭安排，复用已确认的背景与判断 | 主对话、独立任务、可编辑成果 |
| 主动帮助与持续职责 | 关注约定事项，发现变化，提出合适建议，持续推进长期目标 | 生活近况、目标、自动化与活动状态 |
| 专家与团队 | 自建或发现专业 Agent，私聊委托，共同处理一项任务 | Agents、专家目录、协作会话 |
| 个人项目与成果 | 保存资料、决定、工作目录和版本；修改结果后继续协作 | 项目、资料库、按内容出现的编辑工具 |
| 自己的电脑与远程环境 | 在已连接的电脑、常开设备或服务环境执行，了解当前进度并随时接手 | 电脑、任务活动、远程执行工作区 |
| 通信与现实资源 | 连接应用、邮件、消息、日历及服务身份，按具体授权使用电话和付款能力 | 连接器、Agent 资源、授权与回执 |
| 多设备、多模态连续体验 | 在眼镜上看到和说出，在电脑上整理编辑，在手机上补充确认 | 同一个人的认知、同一任务与成果版本 |
| 个人能力与服务分发 | 选择知识与材料，发布有明确用途的专业分身，接受人与 Agent 的委托 | 能力发布、访问规则、服务目录 |
| A2A 协作与交易 | 找服务、协商范围与价格、确认委托、接收交付并验收结算 | Agent 市场、服务详情、委托记录 |
| 社交、合作与恋爱匹配 | 在双方愿意的前提下发现人、了解联系理由、决定是否介绍 | Agent Dating、匹配偏好、双向确认 |
| 可持续更新的个人资产 | 保留原始资料，用新经历和更好的模型更新理解，逐步改进工作方法 | 认知修订、模型选择、技能与学习记录 |

当前未接通的能力可以先提供完整、可操作的前端方案，明确显示 **Dev／开发中**。演示数据、模拟步骤和真实服务状态需要区分；用户能够理解未来可以如何使用，也能知道现在实际能做到哪一步。电话、支付、真实撮合、商业结算和跨设备硬件均按各自进度验收，不与已完成的桌面功能混写。

## 官网中的能力与体验入口

官网以“个人数字分身”为主线，依次呈现持续理解、重要选择中的讨论、可继续使用的任务成果、专家协作，以及未来的设备、服务与关系方向。首页能力内容与当前实现对应，完整产品方向另列开发状态。

| 内容 | 当前可体验范围 | 表达边界 |
| --- | --- | --- |
| 数字分身与导入 | 查看虚构画像、来源和修订；带入摘要，逐条核对确认，再准备可编辑任务草稿 | 官网内容只留在当前页面内存，刷新清空；确认不发送任务，不调用模型 |
| 重要选择 | 在真实产品工作区查看中英文职业方向讨论，核对所用背景并继续编辑提纲 | 四轮会话为作者预设的合成示例，未调用模型，不自动形成个人事实，也不替本人决定 |
| 对话与成果 | 完整应用工作区、文件编辑、版本保存与回看；独立页面保留返回官网入口 | 示例编辑证明交互可用，不证明真实模型执行或外部操作完成 |
| 专家协作 | 复用产品专家目录与工牌，查看角色、团队和示例成果 | 不通过网站调用外部模型或连接真实账号 |

## 持续演进与差异化依据

SecondU 保留原始资料，将新的经历、明确修正、采用结果和实际任务反馈纳入更新。个人事实、偏好判断和办事方法分别维护。随着模型进步，可以重新理解已有资料，比较新旧理解，再更新适合使用的部分。

产品要形成的特色，是把**高质量的个人认知、实际事务执行、跨设备连续体验，以及可控的个人能力分发**组织成一套围绕本人的长期体验。持续积累的个人理解用于推进任务、延续跨设备上下文，并支持用户授权的协作和专业服务。用户始终掌握自己的选择与决定。

记忆、工具调用、主动执行、多 Agent 和 A2A 都有已有产品在探索。SecondU 的差异需要通过整体体验和长期效果证明：用户少重复解释了多少，结果是否更符合本人，跨场景是否真的连续，专业分身是否提供了可信、有用的服务。不能仅凭功能名称宣称独创或领先。

## 桌面交付约束

Desktop scope: assistant/task workspace, social conversation browser, life timeline, interactive relationship graph with accessible list, self-understanding and active life/goals, evidence import/correction, agent creation and QR profile exchange, collaborative agent roles, local automations, BYOK settings, current computer status, artifact editing/version history, export and actual component catalogue. No dead navigation or fake execution statuses. Native desktop wrapper after browser acceptance. Phone/glasses are documented shared-task protocol interfaces, not implemented hardware.

Visual authority: real official Apps SDK UI controls and CSS/tokens. Neutral ChatGPT composition, generous reading space, restrained sidebar, meaningful typography. Main task surface is an ongoing conversation with inline status and expandable evidence, editable result alongside. Cognition views adapt composition to content, not uniform metric-card walls. All pages use the same controls/tokens including error/loading/empty/keyboard states. Do not recreate the rejected green collage. Synthetic demo content is explicitly labelled. Technical internals belong in settings or expandable activity, not everyday copy.

Execution: local user computer first; configurable Responses providers with DeepSeek as demo configuration, not product lock-in. Codex is the first execution adapter. OpenJarvis contributes modular model/engine/tool/memory/trace/evaluation separation; do not nest two harness loops. Credentials are entered by the user, never copied from their other apps. Until supplied, live model integration remains unverified and the UI truthfully shows configuration needed.

Research continuity: preserve Manus Studio/Cue (editable artifacts, on-demand tools, QR agents), Grok Bot (roles, separate memory and shared work, execution/takeover state), Muse (main relationship, independent tasks, goals/library and reviewable memory), OpenJarvis (local-first runtime modules and quality/cost evaluation). Public behavior cannot prove unpublished internals. Detailed research remains in the user's separate private/local archive; this repo retains public source links and adopted/declined rationale only.

Completion evidence: clean setup, typecheck/build, real persistence and revision-conflict tests, execution adapter protocol tests and installed runtime handshake, source/correction task-context behavior, cancellation/restart/approval honesty, actual desktop browser QA and app launch. Credential-dependent live provider validation is explicitly reported if not possible. No public publishing or private-source migration is implied by local implementation.
