# SecondU：完整产品方向与当前原型体验

SecondU 是以个人数字分身为核心的智能体产品。SecondU 持续理解你的背景、经历、偏好、关系和目标，在不同任务、场景和设备之间延续这些理解。组织归拢零散多模态信息，调度合适的专家与工具，主动处理任意想法与事务，并支持协作、社交和专业服务。

三个重点价值：

- 减少背景信息和既有判断的重复输入。
- 让完整的多模态上下文在设备和场景之间连续流转。
- 将经过授权、适当脱敏的个人专业能力分发出去，支持 Agent 之间的协作、社交和交易。

这三项价值用于说明重点，不限制产品的完整范围。[产品定位](PRODUCT.md) 描述完整形态，[产品路线](ROADMAP.md) 说明阶段、当前基础与验收条件。本文的体验步骤和验证证据对应当前可运行原型；跨设备连续体验、专业服务、社交与 A2A 交易的完整形态不等同于已交付能力。

## 产品判断

当模型越来越能执行任务，用户仍需要在不同会话里反复解释自己：哪些事情已经决定，什么约束不能变，谁参与过，上一版为什么被否定。一次回答可以完成得很好，下一件事却经常从头开始。

我认为个人 Agent 的产品机会在于建立一个由用户掌握、不断更新的个人主体。任务和工具围绕这个主体组织：理解来自哪里、这次用了哪些背景、哪些内容应该修正、交付怎样接着使用，都应当成为用户能操作的对象。

这也是 SecondU 采用“数字分身 + 专业 Agent”的原因。数字分身维持对本人的理解；专业 Agent 按职责参与任务。用户可以直接对话，也可以组织一个有负责人的小团队，看清分工、执行和交付。

## 两三分钟在线体验

打开[官网](https://yunyueli.github.io/SecondU/?lang=zh#capabilities)，从首页功能介绍进入实际产品界面。先打开「分身建设」，切换七项材料入口，检查每项入口说明与资料状态；再进入个人画像，查看理解的来源，或打开任务与成果工作区，检查讨论、编辑与版本之间的关系。

网页复用桌面产品组件，无需注册或提供密钥。内置材料明确标记为虚构示例，预写对话不冒充模型执行。页面内导入和修改刷新后清空，网页不连接真实账号或执行模型任务。真实处理请使用 [macOS 桌面版](https://github.com/YunyueLi/SecondU/releases/latest)或按[源码启动说明](../QUICKSTART.md)运行；公开包版本与当前源码进度分别见[更新记录](../CHANGELOG.md)和[构建过程](DEVELOPMENT.md)。

## 从材料到个人理解

「分身建设」提供七项入口：已有资料、文字与笔记、相册、聊天记录、已有记忆、连接资料、说说自己。它们复用同一资料库与已有导入流程，避免把材料建设变成另一套资料管理系统。

| 环节 | 当前可以做什么 | 需要区分的状态 |
| --- | --- | --- |
| 选择材料 | 从已有来源继续；导入文字、照片、视频、聊天记录或记忆；管理服务连接；直接输入近况 | 入口存在、服务连接、资料已同步分别记录 |
| 保存与用途 | 直接输入可选「用于了解我」或「只用于这次」；其他导入先保存原件，再从详情启动处理 | 原件已收到不等于已运行模型或形成理解 |
| 模型处理 | 配置完成的个人空间通过既有执行器处理；未配置时先保存，失败时显示原因并可显式重试 | 待处理、运行中、待审阅、完成与失败分别显示；不中断后自动重放 |
| 本人审阅 | 候选事实、人物与经历提供来源，可采用、修正或跳过 | 个人用途的确认结果进入现有认知；仅本次用途保留处理和审阅，不加入长期画像 |
| 接续任务 | 将已确认内容带入可编辑的新任务草稿，补充目标后发送 | 准备草稿与真正开始执行是两步 |

文字和照片使用同一原件详情。每份原件最多 64 MiB，一份资料最多六个附件；模型输入另有限制，当前抽取支持符合限制的图片或 UTF-8 文本。视频可以保存和回看，视频、PDF 及其他二进制原件不能据此宣称支持理解。长文本的模型输入会明确标注截断；原件全文继续保留。

审阅来源可以检查出处，但逐字引文匹配不能证明每项理解都准确。修正保留原文和反馈，不以新说法覆盖历史证据。

## 连接模型后：五分钟验证主线

在个人空间选择自己的模型连接，并启用本机 Codex 运行环境。首次验证可使用一段合成材料，避免把导入真实私人资料当作检查界面的前提。

| 时间 | 操作 | 核对的证据 |
| --- | --- | --- |
| 0:00–1:00 | 打开「说说自己」，输入一段有明确经历或约束的材料，选择用途后提交 | 原文、用途、是否已经开始真实模型处理 |
| 1:00–2:00 | 查看处理状态与结果，打开候选旁的来源 | 模型任务、来源与候选对应；失败应有原因及手动重试入口 |
| 2:00–3:00 | 逐条采用、修正或跳过；核对确认后的个人画像或本次记录 | 原文保留、审阅决定、版本；仅本次用途不会新增长期认知 |
| 3:00–4:00 | 将已确认理解带入新任务草稿，明确这项背景应怎样影响任务，再发送 | 草稿内容、本轮选中的背景、答复中的实际取舍 |
| 4:00–5:00 | 打开任务成果、编辑并保存一版，再回看原版本 | 实际文件、版本、原件下载；与上下文证据分别核对 |

网页示例可体验界面，不会取得新的模型执行证据。真实提供方已有一次合成文字提取和一次来源变化后主动联系的记录，具体版本和限制见[本轮构建记录](DEVELOPMENT.md#2026-10-19-原件统一与主动联系状态补录)。[个人上下文对照](CONTEXT-BENCHMARK.md)另有 24 个合成场景、6 类能力、3 种上下文条件和两次重复，共 144 次正式尝试、143 次返回；冻结输入、原始回答和失败记录可复查。

## 手机入口与主动联系

「随身入口」复用分身建设、资料与任务组件，支持较小屏幕上的查看、输入、审阅和继续对话。当前入口可在本机浏览器使用，实体手机需另行配置私有访问；不会自动开放网络。手机视口检查与实体设备、相机权限、系统分享扩展、后台唤醒和跨端同步分别验收。

「允许分身主动联系我」默认关闭。在当前空间开启后，新的来源变化先与活跃事项关联，再由模型进行一次只读评估。只有准备了有来源的分析、草稿或判断，并通过状态与去重检查的结果，才进入普通可回复对话。开启不会补发历史资料；关闭会中止评估并拒绝迟到结果。当前需要本机服务运行，尚无云端持续观察、手机系统推送或外部渠道主动发送。具体机制、真实运行和限制见[主动联系说明](PROACTIVE_CONTACT.md)。

现有任务和自动化继续各自承担用户的明确委托。群聊可选择成员、负责人和协作方式；构建过程展示真实提交、设计取舍、当前进度与原文。完整说明见 [Harness](HARNESS.md)、[个人记忆导入](MEMORY-IMPORT.md)和[通信接入](COMMUNICATIONS.md)。

## 运行真实任务

按 [启动说明](../QUICKSTART.md) 安装 Node.js 22.18+、依赖并构建。模型执行需要本机 Codex CLI，模型 Key 在应用内由使用者配置；没有 Key 时会明确停在配置状态。仓库、应用包与示例均不提供开发者凭据。

可用以下公开、无私人资料的任务检查文件闭环：

> 请创建一份活动准备清单 Markdown 文件。活动是一次 6 人读书会，预算上限 300 元，周六下午 2 点开始。列出准备事项、负责人待确认项和预算表；不要购买、发消息或联网。完成后说明哪些条件仍需确认。

随后把人数改为 8 人，要求检查预算并更新文件；再从成果区编辑一处文字、保存新版本、重新打开。这里应核对真实文件、任务记录和版本变化，不能只看助手是否说“完成”。具体提供方对工具协议的支持与输出质量需单独检查。

## 当前证据与限制

最新公开评测采用同一模型和 8,000 字符上下文上限：原始记录检索的决策检查为 48/48，SecondU 上下文为 43/48；按两次重复均正确计，分别为 24/24 和 21/24。H03、H04 遗漏必要来源，R04 一次调用超时，均保留在结果中。这轮合成实验用于定位检索覆盖和运行稳定性问题，不构成个性化质量普遍优于基线的结论。完整[输入、原始回答与分项结果](https://yunyueli.github.io/SecondU/benchmark/?lang=zh)和[实验条件](CONTEXT-BENCHMARK.md)可查看；早期 12 次调用作为历史基线单独保留。

一次真实 DeepSeek 最小团队任务已完成“负责人委派一名专家 → 等待回传 → 汇总”，使用真实 Codex 运行时，共 4 次模型请求；任务和执行树重开后仍保留。这个合成算术任务验证的是执行通路，不证明复杂协作质量或通用能力。

原始文件、版本、消息修改分支、表情、可纠正的背景展示分别有接口或界面验证。完整更新记录见 [构建过程](DEVELOPMENT.md)，设计与实现见 [Harness](HARNESS.md)。每条证据均保留对应范围。

桌面实屏已核对三种 Office（DOCX、XLSX、PPTX）的本机 PDF 预览、DOCX 历史版本、消息编辑分支，以及成果工作区的调宽、展开、Escape 还原和草稿保留。工牌可通过键盘翻面并保留可见焦点。应用包另有运行时、构建指纹、静态资源、原件下载和本机签名检查，具体版本及证据见 [最新交付核对](DEVELOPMENT.md#2026-10-01-发布前文档与应用包核对)。

当前仍是可运行原型：本机服务在线时才能执行定时任务和来源变化评估。分身建设与手机布局已有本机浏览器验收；单项真实模型结果各自保留材料、协议和当时版本范围。实体设备、真实外部账号、远程主机、跨设备传输与长期认知质量需要独立验证。市场、Dating、可穿戴设备场景和部分资源功能仍标注 Dev。Office 预览需要本机 LibreOffice，缺少时仍可下载原件；macOS 本地包采用临时签名，尚未 Apple 公证。

下一步需要验证：与普通对话使用同一份材料、同一个任务时，用户重复补充背景的次数、关键约束遗漏、修正后能否迁移到下一次任务。尚未完成这组用户实验，也没有编造效率提升比例。
