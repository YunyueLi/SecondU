# 远端电脑与持久任务

远端电脑由当前个人空间保存。用户指定主机、SSH 用户、端口和已存在的独立工作目录，再检查运行条件、准备运行组件。当前支持 macOS／Linux、Node.js 22.13 及以上、已安装的 Codex CLI，以及本机已经可信、可免交互连接的 SSH 主机。准备组件不会安装 Node.js、Codex、SSH 密钥或第三方依赖，也不会跳过主机身份检查。

任务只使用本次填写的指令、选择的模型连接，以及明确勾选的已有附件。不会自动复制本机项目、个人资料、数字分身认知、其他任务记录或未选择的附件。模型地址在远端访问；如果地址是 localhost，它指向远端电脑本身。启动前必须确认将该模型凭据用于这一次远端执行，授权同时固定电脑版本、模型版本与请求标识。

## v0.2.1 电脑设置与移除恢复

“设置 → 电脑”在同一页面提供“这台电脑”和“SSH”。本机检测使用固定版本命令，有限时和并发合并；显示当前组件、工作目录和检测时间，失败清除旧版本。检测结果各空间共用，但不会因此宣称模型登录、工具权限或完整任务已成功。

远端列表将添加、检查、准备与执行分开。重新检查会核验当前部署清单中的文件长度和摘要；文件丢失、改动或本机组件版本更新会使准备状态失效，检查不会自动重新安装。较早返回的列表或任务请求不覆盖最新检查结果。

移除电脑保存为可恢复归档，保留历史任务、产物与远程文件。有活动任务、在途请求或执行状态未确认时拒绝移除。恢复后必须重新检查运行条件和准备状态；归档不会修改 SSH 服务、密钥或远端工作目录。设备配对、跨设备屏幕控制和保持系统唤醒尚未实现。

## 运行与恢复

- 本机先保存任务记录，再发出一次启动请求。重复请求返回已有记录；断线、重启或查询不到结果都不会自动重发启动请求。
- 独立的远端进程执行一轮任务，把状态、事件、待审批操作和产物清单保存在远端私有运行目录。本机只是观察者，关闭窗口或应用不会主动取消任务。
- 状态同时记录“远端最后确认的执行状态”和“最近一次连接是否成功”。连接失败不代表任务失败、取消或完成。
- 审批只对应运行器提出的那一次命令或文件修改。拒绝与批准都写入持久记录，重连后可继续查看；不授予整个会话权限。
- 取消请求先记录已送达，只有远端进程实际停止后才显示已取消。任务最多持续 24 小时，默认 1 小时。
- 同一远端用户下，任何空间都不能同时执行两个工作目录重叠的任务。执行进程异常丢失时标为中断；如果仍无法确认其运行器已退出，目录继续受保护。

每轮运行保留固定连接快照。后续编辑电脑或模型不会改变已开始任务的执行位置；新任务需要使用最新版本重新确认。电脑的实际目录或运行器路径在重新检查时发生变化，也会使准备状态失效。

## 数据与产物

上传清单最多 6 个文件、合计 8 MiB，包含附件标识、目标相对路径、大小与 SHA-256。所有清单和目标路径先完成校验，再写文件；已有文件不覆盖，隐藏路径、凭据文件、目录穿越及相互包含的文件路径被拒绝。原始文件内容与模型凭据只随本次 SSH 标准输入传输，不进入启动参数或本机远端任务记录。

运行组件由源码中固定的 17 个文件组成，按内容摘要安装在 `~/.local/share/secondu-remote/releases/<sha256>/`。任务和工作目录锁分别位于同一运行根目录的 `owners/` 与 `workspaces.sqlite`。私有目录、状态文件和组件不允许以符号链接替换；组件与输入文件均验证内容摘要。兼容目录名保留 `secondu-remote`。

产物只收录本轮新建或改动的可见普通文件。单个文件最多 4 MiB，清单合计最多 16 MiB；跳过隐藏文件、凭据文件和包含当前模型密钥等敏感内容的文件。清单不完整时明确标记。下载必须命中本次产物清单，并再次核对大小及 SHA-256；远端后来改动过的文件不会被当作原结果下载。

## 本机 API

所有接口沿用当前空间、来源校验和本机 API 身份边界。示例空间不能检查、安装或执行远端操作。

| 请求 | 作用 |
| --- | --- |
| `POST /api/computer/probe` | 无参数重新检测本机运行组件；不接受自定义命令 |
| `GET /api/computers` | 当前空间活动及归档电脑、带版本号的模型连接与只读状态 |
| `POST /api/computers` | 保存名称、主机、用户、端口与工作目录 |
| `DELETE /api/computers/:id` | 使用 `expectedRevision` 可恢复归档，活动或状态未确认时拒绝 |
| `POST /api/computers/:id/restore` | 使用 `expectedRevision` 恢复连接记录，并清除旧准备状态 |
| `PUT /api/computers/:id` | 使用 `expectedRevision` 编辑；清除已检查、已准备状态 |
| `POST /api/computers/:id/probe` | 检查 Node.js、Codex 和实际工作目录 |
| `POST /api/computers/:id/prepare` | 以 `installRuntime: true` 明确准备运行组件 |
| `GET /api/computers/:id/runs` | 查询本机保存的运行记录 |
| `POST /api/computers/:id/runs` | 按请求标识、配置版本、本次凭据确认和文件清单启动 |
| `POST /api/computers/:id/runs/:runId/poll` | 从事件游标恢复远端状态和记录 |
| `POST /api/computers/:id/runs/:runId/approval` | 决定一条具体审批 |
| `POST /api/computers/:id/runs/:runId/cancel` | 请求取消并等待后续状态核对 |
| `POST /api/computers/:id/runs/:runId/file` | 获取经过摘要复核的文件内容 |

服务在每次保存运行快照后通知任务适配层；由适配层创建独立的主任务记录。新远端运行不能接管正在使用的本机任务，任务列表也不会调用本机执行器来重跑远端记录。

## 验证范围

专项使用独立临时 HOME、工作目录、SQLite 数据库和模拟 Codex 协议程序。运行组件按真实安装流程部署，启动真实独立子进程，覆盖关闭观察后继续完成、数据库重开恢复、审批、即时取消、连接中断、重复请求、配置失效、跨空间目录锁、输入全量校验、产物摘要与凭据保护。模型、主机和输入均为虚构测试材料。

2026-09-30，10 项独立进程检查与 3 项真实 HTTP 接口检查同批 13/13 通过。随后将主任务创建、远端关联和镜像更新纳入同一 SQLite 事务；HTTP 集成扩至 4 项并全部通过，新增故障注入验证失败写入不留下孤立本机任务，重启只恢复一份镜像且不重放远端启动。不同批次与重复回归不累加为同一次测试结果。当前界面仍在验收。

该证据验证本机与远端运行组件之间的进程协议及状态边界。真实网络上的 SSH 主机连通、远端 Codex 版本兼容和真实模型质量需要在用户提供并选定的电脑上另行验收；当前没有声称这些环境已通过，也没有调用真实远端机器或模型账户。

v0.2.1 补充了本机重新检测、远端组件校验、请求竞态和归档／恢复检查，并完成列明的桌面及窄屏界面路径；真实 SSH 主机和模型执行仍遵循上述独立验收边界。详见[开发记录](DEVELOPMENT.md#2026-10-24-连接目录与电脑设置的产品修正)。
