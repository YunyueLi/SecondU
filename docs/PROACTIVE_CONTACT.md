# 分身主动联系：当前闭环与边界

2026-10-19。主动联系进入普通对话，在设置中开启；它不需要独立导航或收件箱。本文描述本次实现和可复核的证据，不将尚未接入的渠道与观察能力列为已完成。

## 产品依据

- Dots 把持续工作与联系渠道分开：同一身份跨端延续，用户可以指定更新去向；监测需要明确对象、信号和通知时机。连接渠道本身不等于授权监测。[官方 Messaging](https://learn.chatgpt.com/docs/dots/channels)
- Dots 的后台主动研究限制为只读；后续实际行动仍遵循既有权限，用户可看进度并改变方向。[官方 Controls](https://learn.chatgpt.com/docs/dots/controls)
- Dots 的持续工作、定时结果与主动更新可回到对话继续。[官方入门说明](https://help.openai.com/en/articles/20001530-getting-started-with-your-dot)

SecondU 据此采用“真实变化 → 评估与准备 → 判断是否值得联系 → 普通对话继续”。词项相交只用于筛出可能相关的事项，不直接生成一条“有新资料”的消息。完整产品方向还包括用户明确委托的持续工作；本轮没有替换已有任务与自动化执行机制。

## 已实现

### 开关、范围与时序

`GET/PUT /api/settings/proactive` 读写当前空间的开关，默认关闭。写入需要 `baseRevision`；并发旧版本返回 409。示例空间不可开启。

启用、关闭都在数据库事务内保存当前资料基线。开启不补发历史资料；关闭期间的资料也不会在重新开启后批量触发。关闭会中止正在执行的评估，并使旧开关版本的结果失效。普通用户已经发起的后续对话和原有自动化不会因为关闭这个开关而被改写。

当前真实接入的观察信号是当前空间中的来源新增、更新：导入回调立即检查，其他导入和变更由已有 `TaskRunner.tick()` 检查。没有新增定时器、Agent 循环或独立模型执行器。活跃待办和近期普通任务都可成为关联事项；没有关联事项时保持安静。

### 一次只读模型评估

每次符合条件的变化持久化为 `twinProactiveEvaluations`。输入仅包含本次来源前 16000 字符及截断标记、上一版对应节选、增加的行、关联事项的有界快照、上次联系内容及该对话的最近回复或显式反馈。不会自动展开完整个人档案或扫描连接器。

没有已配置的模型密钥时，记录保留为 `awaiting_configuration`，不建立模型任务、不伪造联系。已有连接可用后由原调度检查继续。每条变化最多启动一次模型执行；失败和中断不会自动重放。

评估复用 `TaskRunner` 和原生 Codex `extractOnly` 能力。Responses 协议在运行前选择 `outputSchema`；其他既有协议使用预先确定的文本 JSON 校验路径。两者都不在失败后自动切换协议或重试。

隔离不只依赖提示词：运行器验证原生协议，关闭 shell、文件工具、连接器、浏览器、计算机操作、记忆和委派能力；以 `environments: []`、只读权限启动；任何工具、授权或补充输入请求都会被拒绝并使本轮失败。评估任务不绑定项目、不恢复已有会话、不传动态工具。任务标记 `proactiveEvaluation` 并归档，避免把内部 JSON 当普通聊天显示。

### 结果与派送

模型返回严格结构：`quiet / defer / message`、判断原因、实际写出的 `analysis / draft / decision` 文本、可选问题，以及 `sourceId / changeId / excerpt` 证据。

`message` 必须已有非空准备内容和逐字可匹配的证据；更新资料至少引用一处相对旧节选新增的内容。空结果、错误来源、臆造引文、只有旧引文的结果不派送。文本分析与草稿不被记为文件产物、外部动作或已完成待办。

派送事务再次检查：开关仍开启且版本一致、来源指纹未变、关联事项未变或结束、结果在 24 小时内、同事项没有正在处理的任务，以及相同准备内容尚未发过。正在处理同一事项时暂缓；模型主动决定 `defer` 后，同一条记录不再评估或派送，满 24 小时变为过期。只有新的真实变化才形成下一条评估。设置、事项或来源变化也会使旧结果过期。排队期间有其他联系完成时，启动模型前重新读取最新联系摘要，避免使用过早的快照。

通过后建立普通可回复对话，首条为真实模型准备结果，附来源链接和 `origin.generator = model`、`evaluationTaskId`。不伪造用户消息。直接回复使用原来的 `TaskRunner.message()`；后续执行继续遵循普通任务权限。旧版应用提示仍保留 `generator = application`，两者不混淆。

联系、建议和去重记录在同一事务提交。略过只保存本次反馈；答复评价继续使用原有评价接口，不写长期偏好。联系后的用户回复和显式反馈可作为同一事项下一次评估的上下文，但不能自动成为人格或个人事实。

## 尚未实现的部分

- 本轮只接入来源变化这一类事件。具体委托、任务进展、定时运行仍由已有任务和自动化处理；没有把它们再包装成另一套循环，也没有宣称任意生活事件都能自动发现。
- 尚无连接器事件订阅、云端持续观察、手机后台唤醒、系统推送、Slack、短信或主动语音联系。当前消息保存在本机当前空间，需应用服务运行并由现有刷新机制显示。
- 关联候选仍使用确定性词项预筛选，会漏掉词面不相似但语义相关的事项；模型负责是否有新增价值，不代表整个检索系统已具有完整情境理解。
- 当前只知道任务执行状态及同事项回复，不知道用户是否正在看某一屏幕，也没有跨端“已读”或勿扰时段。不能把这称为完整的注意力管理。
- “少联系”“这件事停止”等自然语言策略设置、按事项静音和控制频率尚无专用持久化接口。设置目前只呈现实际可用的总开关。
- 引文与结构校验可以证实出处和输出形态，不能证明每一句分析的语义正确或每次联系都值得打扰。真实运行结果仍需人工审阅；不以一次成功概括长期效果。
