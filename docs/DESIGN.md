# SecondU 桌面设计规范

## Overview

**让个人背景、正在进行的工作和可编辑成果始终有清楚的位置。** 界面采用中性底色、克制导航与适合连续阅读的正文；信息层级依靠排版、留白、分隔和交互状态建立。任务以连续对话推进，资料按其自身结构呈现。已有的绿色拼贴风格不再作为设计方向。

本规范服务于“成熟桌面应用”的质量目标，不构成“已经达到 ChatGPT 全部体验或可访问性水准”的结论。SecondU 直接依赖 **OpenAI 官方公开的 `@openai/apps-sdk-ui` 0.2.2**。该包为 Apps SDK 应用提供设计 tokens、React 组件和工具；不能称作 ChatGPT 内部桌面应用的全量组件库，也不能据视觉相近暗示官方从属关系。

### 来源与状态的解释

| 层次 | 本文含义 | 使用方式 |
|---|---|---|
| **标准** | 新增、修改界面应遵循的规则 | 作为实现和验收要求；未实现的条目不能标为完成。 |
| **实施** | 2026-10-24 从当前工作树核对的代码行为或数值 | 证明存在实现，不证明每个主题、设备或输入方式已正常运行。 |
| **待验收** | 需要在实际浏览器或原生窗口观察、测量和操作 | 验收后写入版本对应的记录，不能用截图外观或测试数量替代。 |

本次校准覆盖源码、设计规则及动效采用边界。[视觉更新验收](qa/visual-refresh/README.md) 与 [ACCEPTANCE.md](ACCEPTANCE.md) 是各自版本的历史证据，不能自动覆盖当前布局、图标与动效变更，也不能据此宣布本轮全部验收通过。实施依据为 [PRODUCT.md](PRODUCT.md)、[产品 tokens](../src/design-system/tokens.css)、[全局样式](../src/styles.css)、[桌面覆盖样式](../src/desktop-refinement.css)、[页面布局](../src/design-system/page-layout.css)、[设置样式](../src/settings.css)、[通用组合](../src/components.tsx)、[主壳](../src/App.tsx) 与 [组件目录](../src/ComponentCatalogue.tsx)。依赖的版本、公开来源和使用声明可从 [package.json](../package.json) 及安装包 `README.md` 核对；公开上游为 [openai/apps-sdk-ui](https://github.com/openai/apps-sdk-ui)。

文首 YAML 是角色和取值的文档摘录。基础产品尺度由 `src/design-system/tokens.css` 定义；最终尺寸同时受桌面及业务样式覆盖，必须按实际选择器、层叠顺序和布局容器核对。控件、颜色与字体语义以官方包为基础。产品 tokens 已进入关键字号、圆角和部分间距；**不表示所有局部数值已完全 token 化，也不表示基础 token 就是每个容器的最终值**。修改尺度时先更新实际来源，再同步本文；不要另维护会漂移的色表或第二套组件实现。

## Colors

### 中性层级

| 角色 | 使用 token | 标准与当前实施 |
|---|---|---|
| 主工作表面 | `--color-surface` | 主内容、任务对话、文稿正文；保持连续阅读空间。 |
| 次级表面 | `--color-surface-secondary` | 侧栏、用户消息、来源原文区域、成果工具栏；表明所属区域，不表示禁用。 |
| 局部区分 | `--color-surface-tertiary` | 头像底、较轻的选中或辅助层；不能用它代替明确的 selected 语义。 |
| 主文字 | `--color-text` | 正文、标题、关键动作与焦点。 |
| 次级文字 | `--color-text-secondary` | 日期、解释、角色、来源提示；仍须达到相应可读性目标。 |
| 弱分隔 | `--color-border-subtle` | 连续列表、壳体、工具栏分区。 |
| 显式边界 | `--color-border` | 输入边界、需要成组的面板、审批、图谱线条。 |

当前兼容别名 `--color-background-primary/secondary/tertiary` 分别指向三个 surface token；`--color-text-primary` 指向 `--color-text`。认知页面沿用这些别名，不形成另一套主题。

产品层的 `--hither-color-canvas/inset/hover/line` 也分别引用 SDK 的主表面、次表面、三级表面和弱边界。这些是业务用途别名，不是另定义的品牌色；新增色彩仍应先选择官方语义。

**标准：** 主操作使用官方 `Button color="primary"`，次级操作用 `secondary` 的 outline、ghost 或 soft 变体。错误、警示等语义色交给官方 Alert/Badge；不以彩色整页背景、关系节点颜色或大面积状态色抢夺正文注意力。成功不强制染绿，确认状态必须有文字。

链接按钮遵从同一规则：`ButtonLink` 的前景、背景、hover 与焦点样式由 SDK 的 color/variant 决定。禁止在未分层的全局 `a` 规则中写 `color: inherit`；这会优先于 SDK 的分层组件样式，使主按钮出现错误前景色。通用链接的继承规则留在基础层，业务链接使用有作用域的类；修复层叠来源，不给每个按钮另补白字或依赖页面背景猜颜色。

`--hither-accent` 是产品选中、聚焦和局部活动柔光共用的强调色。外观仅保留这一套颜色选择，含七种预设（含多彩）与自定义 `#RRGGBB`；多彩在普通控件中使用可读的实色，在活动柔光中使用局部连续多彩渐变。沿边高光不能替代错误、焦点、选中或已连接状态；这些状态必须有各自的文字、图标或语义属性。

**实施：** 主题通过 `html[data-theme]` 切换，设置保留 light、dark、system；system 跟随系统变化。选中文字使用主文字与三级表面。原始 HTML 成果的 iframe 当前是独立白色文档表面，不能宣称任意导入 HTML 会自动适配深色主题。

**待验收：** 在浅色和深色分别测实际计算色。项目目标为普通文字对比至少 4.5∶1，大字号文字及关键控件边界/图形至少 3∶1；不能仅凭 token 名称宣布达标。禁用态仍需与可操作状态区分，错误和已确认状态不能仅靠颜色辨别。

## Typography

统一使用 `var(--font-sans)`；代码、路径和源码编辑使用 `var(--font-mono)`。官方包当前 sans 栈以系统 sans、Apple 系统字体、Segoe UI、Noto Sans 等回退，mono 栈以系统等宽字体回退。不要宣称已完整复用 ChatGPT 私有字体，也不要为某个业务页另换装饰字体。

实际产品字号入口为 `--hither-font-body: 14px`、`--hither-font-label: 14px`、`--hither-font-caption: 13px`、`--hither-font-meta: 12px`、`--hither-font-page-title: 24px`、`--hither-font-section-title: 16px`。新增相同角色直接使用这些变量；欢迎标题、正文内标题和输入字号等少量特殊角色仍按下表处理。

| 用途 | 默认取值 | 应用规则 |
| --- | --- | --- |
| 页面主标题 | `--hither-font-page-title`，24px | 全页唯一主标题；不能当作表单标签。 |
| 设置窗口标题 | `--hither-font-settings-title`，17px / 1.35，550 | 设置与 Agent 详情共用。 |
| 设置内容标题 | `--hither-font-settings-heading`，18px / 1.4，550 | 每个设置页的内容标题。 |
| 普通区块标题 | `--hither-font-section-title`，16px / 1.5，550 | 页面内的下一级分组。 |
| 正文、表单标签、按钮、选中值、页签 | `--hither-font-body` / `label` / `form`，14px | 配置页面不得使用 11–12px 的元信息字号；页签保持单行。 |
| 次级说明、字段提示 | `--hither-font-caption`，13px / 1.7 | 补充当前控件或对象，不替代正文或主要操作。 |
| 时间、版本、次要计数 | `--hither-font-meta`，12px / 1.6 | 仅用于元信息。授权说明、错误和操作按钮不能使用这个角色。 |

### 设置与 Agent 详情的共同基准

2026-09-30 用户明确指定**设置页原有的字号层级**为配置页面基准。此前 Agent 详情局部将正文和按钮写成 11–12px，修正时又错误地通过 `.app-dialog` 重定义全局字号，导致设置页被整体放大；该全局覆盖已撤回。后续必须按文字角色复用现有尺度，不因窗口变大而整体放大文字，也不为塞入内容在窄屏下缩字号。

运行时基础来源是 `src/design-system/tokens.css`，配置表面共用 `src/design-system/settings-type-scale.css` 的 `settings-type-scale` 类。设置、Agent 详情和群聊配置使用相同表单文字角色；类只读取现有 token，不重定义 body/label/caption/meta，也不修改用户的外观字号选择。设置窗口和 Agent 详情桌面上限均为 900×640，标题、页签与底部操作固定，内容独立滚动；简单确认框按内容高度，不能套同一固定高度。

组件库 `#components` 已同时展示基础文字角色及“设置／Agent 详情”的同尺度示例（`src/catalogue/SettingsScaleExample.tsx`），示例复用同一设置字号类与实际 Field、Input、Button 控件。验收需读取实际计算字号、比较同类控件，再实看中文、英文和窄屏布局；不能用源码存在 token 或没有溢出代替可读性检查。

中文以句子和段落建立节奏，不为实现短行而强行断句。正文可使用列表和表格，但不把连续解释拆成标签墙。当前桌面任务与 Agent 对话的阅读主轴使用 `--hither-conversation-width: 768px`；基础 `--hither-reading-width: 740px` 仍存在，不能把它误报为当前对话的最终宽度。文稿约 70ch，认知条目约 70–75ch。长链接、文件名、英文连续字符可断行，原文显示保留换行。大表格、代码块可局部横向滚动，整页不能因此溢出。

## Layout

### 间距与壳体

官方包的 spacing 基础为 4px；产品层已定义 `--hither-space-1` 至 `--hither-space-8`，依次为 **4、8、12、16、24、32、40、48px**。4/8 为紧密关联，12/16 为控件与短内容，24 为面板内距和段落组，32/40/48 为较大分区。新增同类布局直接使用这些 tokens。现有 18、20、21、26 等局部光学校正仍存在，不把它们误写成已消除或另一套通用刻度；新例外应有明确的对齐理由。

| 区域 | 当前实施 | 复用标准 |
|---|---|---|
| 桌面壳 | `100dvh`，侧栏与主工作区并列 | 保留各区域的独立滚动，输入栏不随长对话消失。 |
| 侧栏 | 常态 232px，≤1200px 时 216px | 导航、近期任务、空间身份分组；折叠应增加工作空间。 |
| 顶栏 | 桌面覆盖后 52px；基础声明为 56px | 页面/任务标题、导航开关、本机入口；窄屏页面可以把导航放入自身标题行。 |
| 原生拖动区 | 顶部 30px | 与窗口控制、导航点击区分离；不能覆盖有效点击目标。 |
| 页面内容 | 共用布局上限 `--page-content-width: 1240px` | 一般页面和非沉浸式认知页面复用；具体阅读段落另限行长。 |
| 任务阅读 | 桌面 `--hither-conversation-width: 768px` | 以一条阅读主轴呈现消息、来源、审批和成果入口。 |
| 输入外框 | 桌面与对话共同上限 768px；首页置于欢迎区 | 保持与对话对齐；上下文与角色属于当前任务选择。 |
| 成果并栏 | `clamp(400px,43%,640px)`；≤1200px 时约 46%、最小 360px | 对话保留推进能力，成果可独立预览、编辑、看版本和关闭。 |

不把页面等同于整齐的卡片网格。认识、历史记录、关系和执行消息应分别采用阅读列表、时间轴、图谱加详情、连续对话等结构。所有新结构继续使用同一套控件和 token。

设置页通过分组、留白和字段关联建立密度：当前 `.settings-form` 字段组间距为 18px，设置与组件目录中的 `.form-field` 标签、控件及提示间距为 6px，不再叠加通用 Field 的外边距。面板标题后不重复一段只复述标题的说明；限制、风险和填写要求放在对应字段旁。此处是两个明确作用域的基准，不能据此宣称所有业务字段已统一为 6px。

组件目录按“分类 → 示例名称与规则 → 真实控件”组织，导航及示例名称使用 14px 标签、说明使用 13px、实现名称与计数使用 12px。示例行默认上下留白 24px，以分组标题分隔，不为每一行叠加边线或卡片。源码与业务页面必须引用相同组件；研究材质单独标明采用范围。

### 响应与导航

| 当前断点 | 已有代码行为 | 必须继续验收的边界 |
|---|---|---|
| ≤1200px | 缩小侧栏及页面边距，调整成果比例 | 长标题、两栏输入、较多工具按钮不挤压正文。 |
| ≤1000px | 成果成为右侧覆盖面板；组件目录导航移到上方，分类单行横向滚动 | 成果宽度最多 590px 或可用宽度；目录分类不挤成多行，搜索仍可达。 |
| ≤850px（认知） | 图谱与人物详情上下排，目标约束转单列 | 图谱仍有可用高度，人物列表始终可达。 |
| ≤800px（窗口） | 侧栏为 246px 抽屉，有遮罩；设置对话框距视口四边至少 16px | Escape、点击遮罩、焦点返回和背景键盘隔离逐项检查；不把这个断点写成设置分类重排条件。 |
| ≤730px（设置容器） | 桌面设置隐藏左侧分类，标题栏出现“当前分类＋下拉菜单” | 依据 `settings-workspace` 容器宽度；分类菜单项目至少 44px，不改成换行标签墙。 |
| ≤720px（组件目录） | 搜索与分类上下排列，示例名称与控件转为单列 | 分类继续单行横向滚动；长说明、宽控件和浮层可操作。 |
| ≤650px（认知） | 社交对话变单列，会话列表横向滚动；认知条目重排 | 长姓名、日期和来源标签不遮住操作。 |
| ≤560px | 首页上下文单列，欢迎区和输入控件进一步收紧 | 发送、停止、模式选择不丢失；无需水平滚动整个页面。 |

这些是当前业务断点，不等同于 SDK 内置 Tailwind 断点。页面框架还在 1080/760/420px 调整边距，设置表单在自身容器 ≤440px 时转为单列；应按实际容器容纳内容的能力复用，不能把窗口宽度和容器宽度混为一谈。当前 body 最小宽度为 320px；窄屏至少覆盖 320、360、390px，但不把浏览器窄屏当成手机或眼镜产品已交付。

**实施：** 桌面侧栏折叠状态读取并写入本机 `localStorage` 的 `hither.sidebarCollapsed`，同一浏览器存储环境重开可恢复；存储不可用时仍允许当前窗口切换。窄屏抽屉的开关独立于桌面折叠偏好，不能写成跨设备同步。主题也持久保存。布局通过状态切换完成，未实现可拖拽调节成果栏宽度。

## Elevation & Depth

基础工作表面以底色和细边界区分，主要内容不用投影卡片层层包裹。离开文档平面的临时内容才增加遮罩或阴影。

- **当前实施：** 首页可见输入层有轻投影；弹窗基础样式使用官方 `--shadow-xl`，桌面覆盖使用产品 `--hither-float-shadow`；窄屏成果覆盖层有向左的轻阴影。不能概括为“全站无阴影”，也不能把基础样式写成所有容器的最终表面。
- **标准：** Modal 遮罩只说明交互层级，不代表系统错误。Popover、Select 菜单应盖过自己的对话框，不能躲在弹窗后面；当前有独立的 Radix portal 层级处理。
- **待验收：** 多层菜单、抽屉、成果面板与原生拖动区同时出现时的层级、关闭顺序和焦点。不把 `z-index` 较高等同于交互隔离正确。

## Motion

动效用于解释当前活动、交互反馈或内容进入，不为静态页面制造持续运动。默认以稳定文字和轮廓表达状态；循环装饰只加在当前确实执行的局部状态上。完成、失败、停止、等待批准、等待输入和排队都有各自文案，不能沿用“正在执行”的光效，也不能用动画结束判断任务完成。

### 效果分类与采用边界

组件目录中的[动效示例](../src/catalogue/MotionExamples.tsx)区分七类研究效果。2026-10-25 重新核对原视频后，输入框的当前采用目标另行修正为环境柔光；不能因为旧目录名称含有 Border Beam，就继续把参考解释成光头绕圈。

| 家族 | 视觉与行为 | SecondU 当前采用范围 |
|---|---|---|
| 输入框环境柔光（当前实现） | 稳定表面与基础边框，周围和内侧低透明色光缓慢交替增强、减弱 | 用弥散色区和轻微呼吸表达真实执行；颜色跟随唯一强调色。已检查浅色桌面、深色 320px、减少动态、关闭及完成后停止；完整可访问性与性能结论另行验证。 |
| 沿边光束（Border beam） | 孤立光头及尾迹沿边缘移动 | 不再作为当前输入框目标。摘要小徽标、24 层 SVG 拖尾和后续 conic 细环均已被否定，保留为研究历史。 |
| 整圈光晕（Perimeter aura） | 连续边缘加柔和外围光，不必运动 | 仅目录研究样本；不作为默认卡片外观或运行状态。 |
| 渐变轮廓（Gradient border） | 色彩沿轮廓分布，静态即可成立 | 仅目录研究样本；渐变本身不表示执行、选中或连接成功。 |
| 指针聚光（Pointer spotlight） | 局部亮区随指针位置变化，离开后消退 | 仅目录交互研究；亮区半径随容器限制在 28–68px，每帧最多更新一次局部样式。键盘聚焦时居中静止并保留独立焦点环，触屏保留完整正文与边界。 |
| 内容占位扫光（Skeleton shimmer） | 已知内容结构尚未载入时，亮带穿过占位区域 | 仅目录研究样本；已有内容刷新时保留内容，错误后不能永久停留在骨架。 |
| 镜面扫光（Specular sweep） | hover 或 focus 时扫过一次 | 仅目录研究样本；不自动循环，不暗示后台工作。 |
| 轮廓显现（Contour reveal） | 指针附近的轮廓局部显现，离开后退去 | 仅目录研究样本；与 selected、focus 及实际边界分开。 |

不在整段对话、全部消息、所有连接器或多层嵌套卡片上铺设循环光效。当前运行任务以对话输入框为柔光载体，任务摘要保留状态文字与过程信息；避免同一区域重复叠加循环提示。推广任何研究样本前，先确定它解决的交互问题，再验收真实业务状态。

### 输入框环境柔光的运行规则

**2026-10-25 修正：** 原视频 25.4—28.6 秒显示固定输入框上的宽柔光区迁移和混色，色光明显向表面内侧扩散；右边、底边及圆角可以同时发亮。没有独立尖亮光头带线状长尾的充分证据。此前把研究收敛成沿边追光，再改成极细 conic 描边，仍遗漏了材质与内侧柔光，因此两种方案均已被用户否定。新目标为稳定边框、周围及内侧弥散柔光，并采用用户明确要求的轻微呼吸；这不是对原片呼吸周期的断言。20 张时间采样及 10 张相邻帧的联系表及事实／不确定性见复核归档（本机保存，不随仓库分发）。

[ActivityEdge](../src/design-system/ActivityEdge.tsx) 是可复用的装饰层，调用者拥有真实状态；组件不会请求任务、计时完成或改变进度。参数为 `active`、容器 `radius`、可选 `intensity`（subtle/expressive，quiet 仅保留为 subtle 的兼容别名）、仅供目录研究的可选 `palette`（theme/graphite/violet/teal/amber/spectrum）及仅暂停视觉的 `paused`。默认 inactive；业务不显式传 palette，`active` 变为 false 时立即移除，不等待退场动画。

外观中的呼吸柔光提供关闭、柔和、鲜明（`off/subtle/expressive`）三档，新配置默认多彩强调色＋柔和。颜色由同页唯一的强调色选择控制，包含多彩与自定义 `#RRGGBB`，不再另设流光配色。业务读取 `html[data-activity-effect]` 与实际 `--hither-accent`；当 `html[data-accent=spectrum]` 且未传显式 palette 时，只让局部柔光采用多彩。旧 `activityPalette` 不再是业务外观偏好，也没有 `data-activity-palette` 样式依赖；目录的显式 palette 仍可比较研究色，不写持久设置。选项与色值见[共享外观定义](../shared/appearance-options.mjs)。系统或产品减少动态效果始终优先于样本强度，颜色不承担任务结果语义。

[外观设置页](../src/AppearanceSettings.tsx)已删除独立流光配色行、流光预览大块和永久显示的“已保存”成功标记。更改仍自动保存在当前电脑，错误提示和未保存保护继续按真实状态工作；效果对照保留在组件目录中。

[AssistantWorkspace](../src/AssistantWorkspace.tsx) 与 [AgentWorkspace](../src/agents/AgentWorkspace.tsx) 通过 `isTaskActivityRunning` 复用 [isActivityModelRunning](../src/design-system/taskActivityModel.ts) 的判断，将真实执行状态传给 [ComposerSurface](../src/composer/ComposerSurface.tsx)。仅在任务与模型均为 running，且没有停止中、远端未确认、无活动动作时的审阅阻塞，才启用活动柔光；示例消息修订不触发真实活动柔光。[TaskActivity](../src/design-system/TaskActivity.tsx) 使用相同判断生成状态信息，已不挂载该装饰。状态文案仍可见并独立播报；没有可信百分比时不显示百分比或伪造填充进度。

当前实现为三片低透明弥散色区，在稳定轮廓附近缓慢交替呼吸，保留向输入框内侧的柔和扩散；中央文字、按钮和底色不随之跳动。三片色区、呼吸节奏和外侧阴影范围属于产品设计选择，不能写成原视频使用的技术。浅色、深色、紧凑、展开和手机状态都要观察至少一个完整明暗周期；验收目标是材质、可读性及低干扰，已不以绕行一圈、尖亮光头或长尾作为成功条件。具体参数与实际实现进展分别在当前源码和开发记录中更新。

下表保留**已否定 conic 描边方案**的参数，仅用于理解取舍历史，不能作为新柔光的当前 token 规范：

| token / 几何 | 旧方案值 | 当时的约束 |
|---|---|---|
| `--hither-motion-fast` | 150ms | 简短反馈的基础时长；现存侧栏等过渡另有 220ms 等局部值，不宣称已全部统一。 |
| `--hither-motion-activity-cycle` | 3.6s / 360°，linear | 恒定角速度的视觉节奏，与任务耗时和完成率无关；不是沿周长匀速。 |
| `--activity-edge-core-width` | subtle .75px / expressive 1px | 固定环形遮罩的中性细芯宽度，避免粗管状描边。 |
| `--activity-edge-core-opacity` | subtle .45 / expressive .65 | 细芯读取明暗主题文字色；长尾透明度连续变化，不用多条描边叠加。 |
| `--activity-edge-halo-opacity` | subtle .16 / expressive .22 | 唯一柔光层读取强调色，只出现在前端附近。 |
| 柔光范围 | 1.5px 环形材质、.8px blur，宿主外侧最多 3px 的裁切区 | 限制局部融边；不能扩展成整块底色或高饱和整边，实际亮度与绘制成本待场景验收。 |
| 容器圆角 | 调用者传入；输入框使用 `--composer-activity-radius` | 遮罩固定并随宿主圆角与尺寸变化，渐变变化不旋转容器或拉伸圆角。 |

此前 conic 实现用 `@property` 将 `--activity-edge-angle` 注册为 `<angle>`，在 0°—360° 之间连续插值；`conic-gradient` 提供中性透明度尾迹与前端局部柔光，固定圆角双层 mask 仅保留细环。它替代了 24 条 SVG 描边，但仍把目标约束为轮廓跑动。技术上连续插值不等于视觉方向正确，该机制不再作为当前输入框规范。[@property](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@property)、[mask-composite](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/mask-composite)

**被替代的尝试：** 先前的 `pathLength=100` SVG 方案通过 24 层同头描边叠加形成尾迹，曾用于输入框；用户指出实际画面形成分段、粗蓝带，因此不再采用。更早的摘要小徽标接入也已移除。随后 conic 细环同样被否定；不能将它称作已满足参考的修复。旧研究、原始视频和校验资料保留，但它们及旧实现测试不构成当前柔光方向的验收证据。几何原理与取舍历史见[研究记录](research/2026-10-24-motion-design.md#4-对输入框光效的两次误判与重新复核)。

目录默认使用真实 `ComposerSurface` 组合，在局部浅色、深色区域同步展示输入框；仍可选择宽面板和紧凑状态条作几何比较。局部主题不改应用设置，显式强度与配色不改业务任务。七类材质都有浅深样本；循环样本有暂停入口，骨架样本可切换为加载完成的正文。双主题排列与样本存在只表明实现范围，不代表已完成视觉验收。

旧方案的几何边界仍需如实记录：角度变化不等于非圆形边界上的匀速路程，长边、短边和圆角处的可见速度及亮区长度可能不同。固定遮罩保持圆角形状，但不改变角度与路程的关系；`border-image` 也不会自动按 `border-radius` 裁成目标轮廓。这些技术说明不能反向决定当前应采用跑动描边。[conic-gradient](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/gradient/conic-gradient)、[border-image](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/border-image)

### 可访问性与生命周期

- 装饰层使用 `aria-hidden`、`pointer-events: none`，不接管点击、焦点或朗读。状态文字使用合适的礼貌播报；不要把整个包含按钮的卡片设为 `progressbar`，使内部控件语义丢失。无法确定进度时不设置 `aria-valuenow`。[状态消息](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)、[progressbar](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Reference/Roles/progressbar_role)
- 系统 `prefers-reduced-motion: reduce` 或产品 `data-motion="reduced"` 任一生效即停止流动，启用中的装饰保留静态轮廓；外观选关闭时继续隐藏装饰。设置为 system 不覆盖系统偏好，目录显式强度也不能覆盖减少动态效果。真实状态文字始终独立存在。
- `forced-colors: active` 使用系统 Highlight 静态描边，关闭流动和柔光。焦点环由控件单独提供，不能被装饰层裁切；不可依赖高对比模式中可能被移除的渐变或阴影表达状态。
- 目录中的循环预览提供暂停入口；持续自动运动与其他内容并置超过 5 秒时，应有暂停、停止或隐藏的方式，不能把“装饰”当作豁免。减少交互动效的 WCAG 2.3.3 是 AAA 条目，不应据此误报 AA 已达标。[暂停、停止、隐藏](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html)、[交互动画](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html)
- ActivityEdge 初始暂停，收到可见性结果后再运行；移出视口、文档隐藏或手动暂停时保留相位并停止播放，恢复后继续，不补播离开期间的帧。卸载时断开观察器并移除事件监听。业务任务是否继续运行由任务系统决定，不能以动画暂停推断任务已停止。

### 性能与验收

新柔光方向需要重新核对渲染成本。弥散渐变、阴影、遮罩和 blur 均可能有绘制成本；不能因为主要动画改变透明度，就预先宣称零绘制、纯合成线程、GPU 加速或恒定帧率。可见性处理继续避免逐帧 React 更新，后台和离屏暂停；当前没有新方案的帧率、CPU、GPU 或电耗验收。新增效果仍应限制模糊面积，避免给大量元素永久添加 `will-change`。[动画性能指导](https://web.dev/articles/animations-guide)

验收优先覆盖真实助理与 Agent 输入框的浅色、深色、紧凑、展开和手机场景，再核对目录的双主题输入框、状态条、宽面板与局部聚光。必须检查尺寸变化、真实状态切换、系统及应用减少动效、高对比、移出视口、后台隐藏和卸载重建。至少录制完整明暗周期，检查色区交替是否平滑、轮廓是否稳定、内外柔光是否受控、文字是否始终清楚；静态截图不能证明呼吸自然。性能比较使用 1、8、24 个实例作为正常及压力场景，记录设备、窗口、显示刷新率、帧时间和绘制区域；压力数量不是生产设计目标。60Hz 下约 16.7ms 是一帧总预算，不是仅该组件的可用预算，也不能据一次流畅观察宣称所有设备达标。

本轮稳定边框、周围及内侧弥散柔光与轻微呼吸是新的验收对象，仍在实施与验收阶段。旧版小徽标、24 层 SVG、conic 细环或大范围聚光的截图、录像和回归记录不能自动覆盖这些改动；代码与针对性检查通过后，真实浏览器视觉与性能结论仍需分别记录。

完整研究与采用理由见[动效设计研究](research/2026-10-24-motion-design.md)。公开资料的本地原始快照、来源 URL、采集时间和校验值见研究档案（本机保存，不随仓库分发）；该目录是本机研究材料，不把私人工作数据或运行日志传入公共示例。

Gemini 仅作辅助比较，公开官方素材及观察见独立归档（本机保存，不随仓库分发）和离线查看页（本机保存，不随仓库分发）。已观察素材中，待输入时就存在大范围环境光；这些画面不能证明处理中有沿输入框运动的流光，也不能据此替换当前主界面参照。

## Shapes

业务面板以 12px 为基础，输入框和配置窗口按实际用途保留明确例外。已定义的基础 token 为 `--hither-radius-control: 8px`、`--hither-radius-panel: 12px`、`--hither-radius-dialog: 16px`、`--hither-radius-composer: 24px`；最终轮廓还需读取具体容器的覆盖规则。官方控件使用包本身的 radius 与变体，不能覆盖控件语义来强行统一所有外形。

| 形状 | 规则与实施范围 |
|---|---|
| 12px 面板 | 审批卡、成果入口、独立成果容器、认知分栏外框、约束和协作提示。 |
| 30px 紧凑 / 24px 展开 composer | 会话与手机保留各自的输入形态；桌面首页固定上方两行文本区、下方工具条，可见主表面 26px 圆角，窄屏 24px。首页外层透明，实际轮廓在 `.composer-main-layer`。权限随附件放在主表面底部；项目、文件、连接器、分身和本机入口放在下层。 |
| 含上下文栏的 composer | 普通会话直接包含上下文栏时为 25px，≤520px 时 22px；这是该结构的局部覆盖，不应另建一个全局圆角 token。 |
| 14px 设置与 Agent 详情 | 通过具体对话框选择器覆盖；桌面上限 900×640。 |
| 普通对话框 | 基础 token 为 16px，桌面 `.app-dialog` 覆盖为 22px；不能把其中任何一层误称为所有对话框的最终值。 |
| 8px 控件/行 | 侧栏行、局部来源或代码背景等；官方控件自身仍遵从其 size、pill、variant API。 |
| 圆形 | 头像、图谱节点、少量图标主按钮；不将所有操作变成无文字圆点。 |

这是按职责划分的轮廓，不是把所有内容框都改成 12px。用户消息当前有非对称 20px 气泡，完整成果侧栏是直边分栏；聊天记录也有其消息轮廓。列表和时间轴可以只用分隔线，不为圆角而额外套卡片。

`Dialog` 当前是 SecondU 自有 portal 与焦点管理组合，内部使用官方按钮；关系图是自有 SVG；时间轴和业务布局是自有实现。不能将这些都标作 SDK 官方现成组件。组件目录应呈现应用实际采用的组件和业务状态，不能以组件个数宣称“全量”或“完整兼容”。

### 品牌与连接器图标

品牌优先使用来自官方站点、官方开发者文档或可核实官方发布页的 SVG。位图保留原始清晰素材，像素尺寸至少覆盖实际 CSS 展示尺寸的 2 倍；例如 32px 图标至少需要 64px 源图，但像素足够仍不代表图内标识清晰。不得放大低清缩略图后标为高清，也不凭印象重画、任意改色或裁掉品牌安全区域。

记录来源页面、素材 URL、采集日期、格式、实际尺寸与 SHA-256，SVG 记录 viewBox。当前金融服务与账户图标分别见[金融研究服务来源](../public/icons/connectors/finance-research-sources.json)和[金融账户来源](../public/icons/connectors/finance-account-icon-sources.json)。更新时在组件目录按业务原尺寸检查浅色、深色、透明边缘、留白及相邻标识的视觉大小；下载成功、文件尺寸或截图存在都不能代替清晰度验收。图标与名称共同出现时装饰图隐藏于辅助技术，名称负责识别服务。

### 通用状态矩阵

| 状态 | 标准 | 实施与待验收 |
|---|---|---|
| 默认 / hover | 主次明确；hover 只提示可操作，不承载唯一信息 | 官方控件和业务行已有样式；静态文本不能伪装成按钮。 |
| selected | 明确区分“已选择”和“鼠标经过”；保持文字和语义属性 | 导航用 `aria-current`，按钮/分段选择用 selected，图节点用 `aria-pressed`；跨主题需检查。 |
| focus | 键盘焦点持续可见，不只改极淡底色 | 当前全局按钮、链接及 summary 使用 2px 强调色混合轮廓、3px 偏移；组件目录另用主文字色，SDK 控件保留自身焦点规则。需检查实际对比、裁切和覆盖。 |
| disabled | 使用真实 disabled，说明不可用原因，不能只降低透明度 | 空输入、请求中、缺配置等已有禁用；新增状态须检查原因是否可见。 |
| loading / saving | 显示具体动作并抑制重复提交，保留用户输入 | Button loading、Busy/Indicator、成果保存状态已有实现；异步出错后应恢复操作。 |
| error | 在发生位置说明“什么没完成”和可采取的下一步 | ErrorNotice/Alert 已复用；不得用通用成功提示覆盖服务端失败、版本冲突或过时结果。 |
| empty / no results | 区分尚无资料、筛选为空、连接失败；给一项合适入口 | Empty/EmptyMessage 和列表空状态已使用；不能用同一“暂无数据”掩盖加载失败。 |
| stale / unsaved | 保留当前草稿，说明所见版本或旧缓存 | 成果有脏状态、版本冲突提示；断连显示上次内容与重试，不能伪装实时。 |

### 桌面业务模式

| 模式 | 用户必须看见的内容 | 当前实现与明确边界 |
|---|---|---|
| **任务与协作** | 连续对话、当前模式、状态、所选认知、分工、审批、成果；活动细节按需展开 | 本地演示与模型任务分开；角色输出带身份。多角色为顺序角色轮次，不用视觉动画暗示并行自治。 |
| **认知与证据** | 陈述、已确认/推断/待确认/已替代、来源入口、版本与修订原因 | 可纠正、查修订、用于任务。来源原文与认知判断分别呈现；历史任务显示本轮快照。来源摘录和完整原文不能混称。 |
| **社交对话** | 会话列表、参与人、原始消息、时间、关联来源与示例标记 | 当前是已保存记录浏览，不是正在给真实联系人发消息；不能使用“已送达”等未实现状态。 |
| **人生时间轴** | 日期、事件、关联人、来源和类别 | 日期轴服务检索和回忆，不用装饰性成就徽章替代事实；窄屏保持日期与内容关联。 |
| **人物关系** | 图、可键盘操作的人物列表、选中人物详情、关系说明与证据 | 图节点和列表均能选择；线与位置不表示未经定义的亲密度或因果强度。需验收 SVG 与辅助技术的真实可访问性。 |
| **目标与当前生活** | 可推进目标、状态、期限、个人限制 | 目标列表和约束并置；“标记完成”是用户的明确操作，不能依据漂亮的计划自动完成目标。 |
| **助理与二维码** | 角色名称、分工、指令；导入预览与明确确认 | 可导出名片、从图片或文本解析；不把扫描等同于执行指令。二维码留白、对比和真实解码须验收；摄像头扫码不属当前实现。 |
| **单次审批** | 动作、范围、可展开细节、拒绝与“允许这一次” | 审批嵌入任务；处理过的审批有历史。不能默认勾选未来授权，也不能把关窗当批准。 |
| **成果与反馈** | 预览/编辑/版本、保存状态、下载、与任务的关系；中断产物的待验收提示 | Markdown 与受限 HTML 预览已实现；有草稿恢复与冲突保护。保存不等于发布，任务完成不等于外部结果已人工验收。 |
| **设置与自动化** | 模型配置是否齐全、本机是否在线、测试范围；触发条件和最近任务 | 默认服务商只是预设；文本连接测试不认证工具/多模态。本机离线时不能显示任务仍在执行。 |

### 键盘与辅助交互

**标准：** 全部主流程都可不用鼠标完成。图标按钮有可理解的名字，表单有可关联的 label，错误不是仅靠 placeholder 或颜色表达。新增提示应和对应字段关联，加载与保存反馈使用适当的状态播报，不能把整段日志持续塞入强制播报区。

**代码已具备：** 跳到主内容、导航 `aria-current`、关系节点 Enter/Space 操作、任务输入 Enter 发送与 Shift+Enter 换行并避开中文输入法组合态、成果 Cmd/Ctrl+S 保存、Cmd/Ctrl+K 开始新任务、Cmd/Ctrl+Shift+F 展开导航并聚焦任务搜索；Dialog 有初始焦点、Tab 环绕、Escape、背景 inert 与关闭后焦点恢复，并对 Select 的 portal 做处理。

**仍需实测：** 折叠侧栏时搜索快捷键是否真正展现并聚焦输入、窄屏抽屉与覆盖成果的焦点隔离、菜单与对话框的 Escape 顺序、所有图谱节点能否被辅助技术正确读取、200% 缩放、中文输入法、连续轮询时焦点与滚动位置是否稳定。代码中有处理函数不等于这些组合均已通过。

紧凑桌面交互目标的项目目标至少 24×24px；主要动作优先 36px 及以上，触摸场景目标为约 44px。当前存在 24/26/28px 的来源和轻操作，不把它们写成已满足全部触摸场景。界面缩小时不应只缩字号和按钮来塞入内容。

## Do's and Don'ts

### 持续维护规则

- **Do：** 用官方语义 token 和实际导出控件；新业务组合同步添加可操作的目录示例。修改依赖版本时重新核对默认样式与交互。
- **Do：** 关键页面同时准备长内容、空数据、错误、处理中和待用户处理状态；让样式对应真实数据状态。
- **Do：** 让来源、认知修订、任务快照和待验收成果可追溯；示例资料一直保留明确标记。
- **Do：** 复用面板、紧凑及展开输入框的既有轮廓、统一阅读宽度与中性层级；必要例外写出职责和范围。
- **Do：** 动效绑定真实状态，减少动态效果时保留信息；品牌图标保留可追溯来源并按业务原尺寸验收。
- **Don't：** 将用户主线改成指标卡片墙、绿色拼贴、无意义渐变或每页一套视觉语言。
- **Don't：** 把 SDK 包的公开组件目录说成 ChatGPT 内部完整实现，或把相似外观说成官方认可。
- **Don't：** 只用鼠标截图、构建成功或自动测试通过证明键盘、对比度与原生交互已成熟。
- **Don't：** 省掉错误、草稿、拒绝、断连和中断状态来得到更整洁的演示。

## 2026-09-30 可读性修正

用户明确指出分类、子导航、筛选和表头偏浅、偏细，要求参照 ChatGPT 改善整套界面的可读性。保留官方 SDK 字体与控件；产品文字角色调整为正文/标签14px、说明13px、元信息12px，用户字号设置继续生效，元信息下限12px。自动化表头采用13px/500/正文色，正文与标签不以低透明度区分。主库资料不参与第三方视觉审查。

颜色沿用 SDK 的灰阶：浅色次要正文使用 gray-600，元信息使用 gray-500；深色分别使用 gray-800/gray-700。不是修改厂商包。导航、表头、表单和内容区域分别实测计算值，控件的禁用状态仍保留。将多页9–11px固定说明文字替换为元信息token，避免用户缩放时仍固定得很小。最终宽窄屏、暗色对比和拥挤状态随本轮验收记录更新，不用本条设计说明代替结果。

### 相关页面入口

区块标题旁的时间轴、图谱等入口复用 `src/design-system/SectionLink.tsx`：官方 ButtonLink、secondary / outline / sm、14px 标签及右箭头。保留真正的链接语义和官方 hover/focus-visible 状态，不使用看起来像普通文字的裸链接。组件库“导航与浮层”包含同一组件的实例。

### 通信平台选择

导入记录、通信工具连接与组件库共用 `src/cognition/PlatformSelect.tsx`。触发器和选项都显示相同品牌图标，保留搜索与选中标记；菜单左对齐，宽 220px（最小 190px，最大 240px），不随整列输入框拉宽。平台名称来自同一映射，OpenClaw 的 `msteams` 复用 Teams 标识。新增平台字段必须调用该组件，不单独重建纯文本 Select。

### 首页推荐任务

首页推荐项与组件库共用 `src/design-system/SuggestionRow.tsx` 和 `RecommendationIcon`。任务语义与品牌来源集中在 `shared/recommendation-icons.ts`：28 种任务类型覆盖研究、写作、反馈、演示、旅行、家庭、健康、日程、预算、购物、编程、学习、求职、音乐、摄影、饮食、运动、阅读、邮件、会议、数据分析、翻译、设计、视频、归档、提醒、对话与文档；18 个应用品牌直接复用 `PlatformIcon` 的现有素材与署名，不另画品牌图标。

匹配顺序固定为：有效的显式 `app` → 有效的显式 `kind` → 内容中明确出现的应用品牌 → 中英文任务关键词 → 通用 Chat／Document。显式类型不被文案猜测覆盖；未知 `app`／`kind` 安全回退。英文关键词按词边界匹配；LINE、Signal、Matrix 等普通词不会单独触发品牌。解析函数只读取当前推荐文字的前 2000 字符，不调用模型、不联网、不保存文字。原 `feedback` → Chat、`trip` → Calendar、`presentation` → FilePresentation 映射继续有效。

前置图标保持 18px、图文间距 12px；整行保留链接、完整任务文字与右箭头。纯文本推荐可以直接省略 `kind`，由文字匹配；复杂 React 内容应传 `iconText`，已知应用或任务类型时显式传入 `app`／`kind`。图标本身隐藏于辅助技术，完整文字负责说明任务。组件库的「推荐图标目录」可筛选全部类型与品牌，并用同一个解析函数预览匹配结果与依据。

首页示例任务通过当前资料集的 `profile.exampleTaskIds` 选择，不写死中文任务 ID；无列表时使用前三个未归档、已完成的普通任务。
