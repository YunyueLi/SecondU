# 桌面验收记录

日期：2026-09-29。版本：0.1.0。只使用虚构示例、本机测试提供方与临时执行目录；没有读取或迁移私人数字分身原文，没有使用第三方模型密钥，也没有对外发送消息。

## 已验证

- `npm run build` 通过，直接依赖官方 Apps SDK UI 0.2.2。业务图谱、时间轴与编辑器使用同一套颜色、文字、输入和状态体系。
- `HITHER_TEST_REAL_CODEX=1 npm test`：**42 项通过，0 失败，0 跳过**。包含已安装 Codex 的真实离线握手、允许目录内写入、禁止目录外读写，以及取消前不启动模型；不等同于模型推理完成。
- 实际浏览器从主界面创建任务。发现并修复无请求体 POST 缺少 JSON 请求头的问题，任务可进入单次写入审批。
- 将示例预算 2000 元纠正为 800 元，保留第 1 版与原因；任务读取第 2 版认知，文稿限制实际变为 800 元。历史任务展示执行快照。
- 批准一次本地写入后生成真实 Markdown；成果侧栏可预览、编辑、保存到第 2 版。下载与历史版本由持久实体支持。
- 生成助理二维码，实际从 PNG 图片识别、显示预览、确认后创建；再编辑为“文稿伙伴”。没有自动访问链接或运行二维码指令。
- 在模态内实际操作官方 Select，创建资料导入触发的本地演示；导入一份结构化对话后出现待审批任务。测试自动化随后暂停。
- 实际查看社交对话、来源、人生时间轴和关系图，编辑关系背景；深色主题的图谱和导航保持可读。
- 设置页明确显示 DeepSeek 预设、用户自己的密钥输入、当前电脑与执行器。未输入密钥时“保存并测试”禁用，未报告真实模型连通。
- 审查修复了错误模型响应误报成功、旧配置测试污染新配置、所选证据未进入任务、来源覆盖、自动化任务堆积、失败／取消前成果丢失等问题。具体复现与测试见 [REVIEW.md](REVIEW.md)。

## 原生验收

- 实际启动 `out/Hither.app`，生产界面在原生窗口正常渲染，使用打包资源和本地字体；本地 ad-hoc 签名通过 `codesign --verify --deep --strict`。应用包不包含测试数据库或凭据。
- 原生资料固定保存到 `~/Library/Application Support/Hither/data`，与开发预览的 `.hither` 分开。启动按 `spaceId` 核对已有服务，不会因为同名、同版本而误连开发空间。
- 在等待写入确认时退出应用，再打开：同一任务、消息、认知快照保留，任务显示“已中断”，旧批准失效。点击“继续任务”后重新请求单次批准，写入新的持久任务目录。
- 在原生窗口批准本地写入，得到真实 Markdown 第 1 版；编辑保存第 2 版。后续拒绝新的写入，任务成为 cancelled，已有第 2 版成果仍可打开。
- 补充任务反馈，点击“记为个人反馈”，编辑长期表述并保存：自我认识页显示“待确认”，关联单独保存的反馈原文。没有自动变成已确认事实。
- 成果编辑后先不保存，切到“当前生活”再返回，草稿仍在；继续保存成为第 3 版，界面显示新版本与成功状态。`native-artifact.png` 保存了该结果。

## 仍有明确边界

- 未进行真实 DeepSeek 或其他 BYOK 提供方的端到端调用，因此未证明真实推理、工具成功率、多模态或成本性能。
- 数字分身的理解精度需要在用户授权、脱敏且带评测基线的真实资料上继续验证；本轮不能据虚构例子宣称达到 AGI 或高精度数字分身水平。
- 多角色实现是同一任务下的顺序独立角色轮次，不宣称并行群体自治。每个角色的真实模型执行都受同样边界约束。
- 手机／眼镜、远程电脑配对、电话／邮箱／支付、摄像头扫码、视频编辑、Jev 性能层未在本轮实现。接口预留见 [DEVICES.md](DEVICES.md)。
- 应用仅本机使用，未签发 Developer ID、公证、发布仓库、上线云服务或公开私人资料。
