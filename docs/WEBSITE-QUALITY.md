# 官网品质标准与验收

本页说明 SecondU 官网的设计、可用性、性能与发布检查标准。设计参考包含 Awwwards、The Webby Awards 和 FWA 的公开评审维度；这些参考不代表产品获得了奖项或认证。

产品能力边界见 [产品定位](PRODUCT.md#官网中的能力与体验入口)，功能变化与发布版本见 [开发历程](DEVELOPMENT.md) 和 [迭代清单](ITERATION.md)。下方历史检查只适用于注明的版本与条件。

## 官方标准及采用方式

以下来源于 2026-10-08 核对的官方页面。评审机制可能变化，正式参评前重新核对。

| 来源 | 官方维度 | SecondU 对应的检查重点 |
| --- | --- | --- |
| [Awwwards Evaluation System](https://www.awwwards.com/about-evaluation/) | 设计 40%、可用性 30%、创意 20%、内容 10% | 构图、字体和材质形成完整表达；用户能顺畅阅读、操作和进入产品；原创交互服务于数字分身主题；内容具体、可信 |
| [The Webby Awards Judging Criteria](https://www.webbyawards.com/judging-criteria/) | 当前网站类别包含内容、结构与导航、视觉设计、功能、交互、创新、整体体验 | 从理解产品到实际参与形成连续体验；检查加载、跨浏览器、访问需求、导航预期和交互反馈，不能只检查首页画面 |
| [FWA 官方介绍](https://thefwa.com/FWA25/25.html) | 强调数字创新、创造性、原创性和技术质量 | 保留有辨识度的艺术方向，让细节、交互和实现共同服务于产品表达。此页面是官方方向说明；本轮没有核实到可引用的数字权重 |

官方维度用于确定检查范围，不换算为自评获奖分数。功能检查、性能测量与页面视觉需要分别验证。

## 保留的艺术与产品方向

- Hero 保留已经确认的完整双面人物、奶油色与淡紫色油画材质、粒子边缘及层次。纸面、水彩与手绘质感贯穿插画、背景和细节；不要把不同材质统一成单层模糊或通用科技光效。
- `2ndU` 保持固定字符顺序和正立方向。粒子反馈、首次聚合及局部悬停遵循既定行为，文字与按钮周围保留安全距离，不能因增加效果而降低可读性。
- 保留现有字体、配色与中英文分别调整的比例。标题、正文和真实产品界面的字体角色清晰，避免把整站排成同一种展示字号。
- 展示真实 SecondU 组件、专家工牌、对话和可编辑成果。官网示例继续明确标注虚构内容、页面内状态与执行边界，不用装饰性模拟界面证明尚未存在的能力。
- 手机端按阅读与操作重新组织内容。桌面构图可以调整为适合窄屏的顺序，完整产品方向、状态说明和操作能力仍应可达。

## 每轮检查与修正

每轮先固定候选版本、入口、浏览器、尺寸、语言和主题，实际滚动并操作受影响页面，记录具体问题及其后果。修正后在相同条件下重开页面；涉及公共组件时补查受影响的其他组合。只有看到新行为和新画面，才把对应问题改为已验证。

每条记录至少包含：问题、发生条件、实际修改、验证结果、证据位置和剩余限制。通过后不重复扩大同一批检查；发现新变化、失败或未解决问题时，再进入下一轮。保留历史失败及其范围，不能用新版截图改写旧版结果。

## 发布前的可验证门槛

以下用于确认候选版本是否完成本轮验收。检查对象必须是最新组合构建；开发服务器、旧截图和前序专项结果分别标注。

| 范围 | 验收要求 |
| --- | --- |
| 内容与产品叙事 | 首屏能说明 SecondU 的作用，并提供明确入口。首页产品窗首次出现时即可看到有意义的对话、背景或成果；开启减少动态效果后仍能理解。现有能力、开发中方向、虚构演示与真实执行不混写 |
| 全页视觉 | 实际检查 Hero、产品窗、能力、专家、路线、隐私、流程图、评测、开发记录和页尾。没有文字遮挡、图片缺失、意外留白、裁切、失衡间距或横向溢出；加载完成后再判断懒加载区域 |
| 语言、主题与尺寸 | 覆盖中英文 × 浅深主题 × 桌面和手机宽度的八个基本组合。记录实际尺寸；1440×1000 与 390×844 可作为对照条件，另查 320px 窄屏及 980px 路线布局切换附近。Chrome 与 Safari 的受影响页面分别检查；浏览器窄屏仿真与真实手机硬件分开记录 |
| 导航与连续操作 | 所有主要入口到达文案承诺的位置。进入产品、切页、展开、收起和返回可以连续完成；页面不因一次选择意外跳到远处。手机路线详情靠近所选阶段，仍可继续选择其他方向 |
| 键盘与可访问性 | 用 Tab、Shift+Tab、Enter、Space 和 Escape 实际操作导航、语言/主题、轮播、路线和产品入口。焦点可见、顺序合理；打开体验后焦点进入目标，收起后回到实际触发者；无键盘陷阱。标题层级、按钮名称、选中状态、图片说明和动态反馈与可见界面对应 |
| 动态与静态体验 | 系统减少动态效果启用后，装饰动画和自动播放停止，内容与功能保持可用。手动暂停/恢复有准确状态；离屏、后台标签页和暂停状态不继续提交无必要的装饰绘制。保留静态后备图，不因 WebGL 不可用而出现空白 |
| 主题首帧 | 首页、英文入口和独立评测页在 React 启动前读取已存偏好或系统主题。存储被禁用时仍能打开；切换主题及系统主题变化后保持一致。实际观察冷开页面，不能只靠最终 DOM 判断没有闪白 |
| 嵌入与异常 | 验证首次加载、交互接管、暂停、语言/主题切换及页面内草稿保留。慢请求与明确失败分开；重试有真实入口，不能用自动重载掩盖错误或清空内容。检查 iframe、图片、视频、字体及子路径资源的实际请求 |
| 双语入口与分享 | 不运行 JavaScript 读取中文首页和 `en.html`，核对各自 title、description、canonical、hreflang、OG、Twitter 与图片地址。旧 `?lang=` 链接继续有效；切语种保留其他 query、hash 和页面内内容。静态标签通过不等于社交平台卡片已验收，真实平台预览另记结果 |
| 素材与公开边界 | 只交付显式白名单内的公开素材，验证源与输出哈希、尺寸、透明边缘及实际显示质量。原图保持，压缩只作用于网站交付。私人资料、凭据、原始聊天、个人日志和本机审查截图不得进入公开构建 |
| 工程与发布 | 相关测试、网站类型检查、生产构建和资源守卫通过；记录对应版本或构建清单。发布后再读取真实网址核对部署版本、关键入口和资源。构建、部署、浏览器验收与用户采纳分别记账 |

发布检查以实际页面和运行结果为依据，覆盖本次修改影响的视觉、键盘、交互和性能。保留未验证范围，避免将单项检查扩大为完整产品结论。

## 性能证据的解释范围

性能记录须注明 URL、候选版本、浏览器、视口、像素比例、网络设置、缓存状态、采样时长及测量方法。开发服务器与生产构建、冷缓存与热缓存、实验室网络与公网分别记录；前后对比使用一致条件。

图片字节减少说明交付资源更小，不直接等于首屏更快。实际传输还取决于加载时机、缓存、压缩与访问路径。页面 requestAnimationFrame 反映主线程调度，WebGL 提交帧反映发出的绘制调用；两者都不能证明 GPU 完成时间或所有设备恒定帧率。本机运行也不能替代真实用户的 LCP、INP、CLS 数据。没有取得的指标写为未测，不用近似指标充当结果。

最终性能复核至少覆盖首屏冷开、完整滚动、关键交互、暂停、离屏与后台恢复，并检查新增资源及长任务。数值异常需定位到具体工作或请求；不能为得到更高分数删去已确认的产品表达。

## v0.1.4 网站检查摘要

2026-10-08 的检查覆盖中英文、浅深主题、桌面及手机宽度，以及 Chrome 与 Safari 的相关入口。已验证暂停后的静态画面、手机路线详情、键盘进入与退出产品、焦点返回，以及网页示例文档的编辑、保存和重开。手机检查使用桌面浏览器窄屏视口，未覆盖真实手机硬件。

中文首页、英文首页、评测页和分享图已检查；分享图为 1200×630 JPEG。真实社交平台抓取、卡片裁切、完整屏幕阅读器体验及所有设备组合仍需单独验证。
