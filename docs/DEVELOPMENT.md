## 01　确定产品闭环，而非拼接功能入口

**问题。** 长期记忆、主动执行、多 Agent 与跨设备本身不足以说明这个个人 Agent 有什么独立价值；私人数字分身库也不能直接成为公开产品的演示数据。

**取舍。** 将“用户可以纠正系统对自己的理解，而且下一次任务确实受影响”作为主线。应用维护来源、事实状态与版本、任务、批准和成果；Codex 负责单次执行内的 Agent 循环及工具沙箱。OpenJarvis 用于模块边界与轨迹评测参考，没有再套一层竞争的执行循环。手机、眼镜和 Jev 留作接口与研究边界。

**改动。** 新建独立桌面项目，只放明确虚构的示例。界面直接依赖官方 Apps SDK UI；原始竞品页面、视频与私人实践材料继续留在各自档案中。

**验证与遗留。** 这是一项产品与架构决策，不等于模型质量已验证。对照组、任务质量、延迟和成本仍需要后续带真实模型的评测。详见 [产品目标](PRODUCT.md)、[设计来源](RESEARCH.md)、[OpenJarvis 采用边界](OPENJARVIS.md)。

## 02　首版：把认知、任务、成果和反馈连起来

**提交。** `50d5e1f9b0a0092a12f44b732de732199e52c14b`，2026-09-29 12:50:01 +08:00。提交主题：`Build local personal agent desktop with traceable cognition and controlled tasks`。

**问题。** 一个能聊天的壳不能证明个人背景真正参与了执行；审批、停止、失败、成果编辑与重启的边界如果不明确，就会把“界面显示完成”误当成任务完成。

**取舍与改动。** 用 SQLite 和本机文件保存真实状态；每次操作单独批准。事实修订保留版本和来源，任务保存使用的认知与证据快照。成果可以编辑、查看版本、恢复草稿；反馈先成为待确认候选。原生资料目录与开发空间隔离，重启令旧审批失效，不自动重放未知副作用。

**实际发现并修复。** 空 POST 缺 JSON 头导致任务不能启动；错误模型响应被误报成功；旧配置测试污染新连接；任务只带来源 ID 而无法查证；干净编辑器遇后台新版本误判草稿；历史任务误展示最新认知。这些问题的复现和修复保留在 [独立审查](REVIEW.md)，没有在完成后删掉失败历史。

**验证。** [首版验收](ACCEPTANCE.md) 记录 42 项通过、0 失败、0 跳过，生产构建、本地签名及原生启动。实屏完成预算纠正后任务采用新版本、单次批准写入、成果编辑、退出重开后继续、拒绝新写入但保留旧成果、反馈保存为带来源的候选认知。

**遗留。** 真实 Codex 握手与操作系统沙箱通过，不等于真实 BYOK 提供方推理与工具任务通过。首版没有宣称云电脑、手机或眼镜硬件可用。
