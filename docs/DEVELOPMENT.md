## 01　确定产品闭环，而非拼接功能入口

**问题。** 长期记忆、主动执行、多 Agent 与跨设备本身不足以说明这个个人 Agent 有什么独立价值；私人数字分身库也不能直接成为公开产品的演示数据。

**取舍。** 将“用户可以纠正系统对自己的理解，而且下一次任务确实受影响”作为主线。应用维护来源、事实状态与版本、任务、批准和成果；Codex 负责单次执行内的 Agent 循环及工具沙箱。OpenJarvis 用于模块边界与轨迹评测参考，没有再套一层竞争的执行循环。手机、眼镜和 Jev 留作接口与研究边界。

**改动。** 新建独立桌面项目，只放明确虚构的示例。界面直接依赖官方 Apps SDK UI；原始竞品页面、视频与私人实践材料继续留在各自档案中。

**验证与遗留。** 这是一项产品与架构决策，不等于模型质量已验证。对照组、任务质量、延迟和成本仍需要后续带真实模型的评测。详见 [产品目标](PRODUCT.md)、[设计来源](RESEARCH.md)、[OpenJarvis 采用边界](OPENJARVIS.md)。

## 2026-09-30 任务权限与运行时用量

本机任务增加 `ask / auto / full` 三档权限，空间默认通过 `GET / PUT /api/settings/execution` 读取、保存，Bootstrap 返回 `executionSettings`。任务与 Agent 会话可保存 `approvalMode`；显式 `null` 表示下一轮继承默认。新任务省略该字段时快照当前默认，历史缺字段任务保留原来的 `ask`。每轮启动保存 `resolvedApprovalMode` 及策略事件，运行中或等待审批时禁止改任务配置。

- `ask`：`on-request`、`approvalsReviewer: user`，保留任务目录可写、最小系统可读、网络关闭的命名权限。

`thread/tokenUsage/updated` 的 `last.totalTokens` 保存为 `Task.contextUsage.usedTokens`，`modelContextWindow` 保存为容量；`total.inputTokens/outputTokens/totalTokens` 保留为当前模型会话的累计消耗，不能充当当前上下文。多 Agent 任务保留当前或最后执行者的测量，并附 `agentId/model/threadId`，不把多个模型的上下文相加。缺失字段为 `null`，切换模型或权限、开始新轮次时清除旧显示。Chat 与 Messages 转接不再将缺失的供应商用量伪造为 0。
