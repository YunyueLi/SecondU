## 历史工作记录：2026-09-30 早期追加反馈

以下记录早期产品方向与后续采用的方案。专题协议见对应文档，最新功能状态见[当前迭代](ITERATION.md)。

### 产品与品牌

产品名称统一为 SecondU，符号、字标、工牌、原生菜单与图标使用同一品牌体系；兼容身份仍保留旧名称。

核心闭环围绕个人资料整理、按需召回、理解纠正和任务执行。对话、专家、项目、自动化与受限分身共用已有资料和任务机制。跨设备与服务网络保留在后续路线。

### 真实内容与使用

个人空间从空库创建，与虚构示例的资料、任务、凭据和草稿独立。导入保持原始证据与引用，重复进入不清空记录，重启后保留任务和成果。

示例只承载明确编写的虚构内容；真实记录由使用者在自己的本地空间管理。

### 界面纠正与验证

个人画像按身份、经历、偏好和处境组织；待办支持日期、旗标、完成与重开、自定义清单。时间轴按日常活动聚合，支持图片与人物关联、大图浏览和键盘操作。

设置采用固定标题和分类、正文独立滚动。联系人列表可调整宽度，文件工作区保留编辑草稿与历史版本。相关保存与响应式流程检查通过。

### 通信、资源与分发

外部通信采用能力检查、消息预览、来源保存、回复草稿、明确发送确认和回执。超时或回执不匹配保持未知状态。

电话、邮箱、付款资源采用独立绑定与权限规则。受限分身按能力、脱敏资料与接收者授权提供链接或二维码；角色卡导入与实际能力调用分开。

### 收尾原则

每个版本分别检查源码、实际界面和原生包。公开说明聚焦行为变化、适用范围与使用者需要知道的限制。

## 01　确定产品闭环，而非拼接功能入口

个人 Agent 的核心问题是：用户能否纠正系统对自己的理解，并让下一次任务实际采用这些变化。

SecondU 用来源、事实状态、版本、任务审批与成果记录连接这个闭环。Codex 负责单次执行循环和工具沙箱，OpenJarvis 用于模块边界与轨迹评测参考。桌面作为首个落点，手机与眼镜围绕同一任务继续探索。详见[产品目标](PRODUCT.md)、[设计来源](RESEARCH.md)和[OpenJarvis 采用边界](OPENJARVIS.md)。

## 02　首版：把认知、任务、成果和反馈连起来

首版提交 `50d5e1f` 使用 SQLite 与本机文件保存任务状态、上下文快照和成果版本。审批对应具体操作，反馈先保存为候选认知；重启后恢复查询，不自动重放未知副作用。

早期修复包括空请求缺少 JSON 头、模型错误被误报成功、配置检查影响后续连接、任务缺少来源正文，以及后台版本变化覆盖编辑草稿。成果编辑、拒绝写入、纠正后采用新背景和退出重开均完成检查。详见[首版验收](ACCEPTANCE.md)与[独立审查](REVIEW.md)。

## 03　视觉与组件：从“能用”走向可持续维护

提交 `7d8bc54` 统一采用官方 Apps SDK UI 与产品 tokens。对话、个人认知、图谱和成果按内容使用适合的布局；审批、成果卡和来源标签由目录与业务页面共用。

组件目录提供实际可操作的控件与组合，设置分组保留草稿。明暗主题、弹窗、焦点返回、窄屏成果和原生启动经过检查。设计规则见[DESIGN](DESIGN.md)。

## 04　第二轮：从功能目录转向真实使用路径

第二轮把专家、个人认知、模型连接、项目与资料放回完整任务路径。以下章节保留主要设计与工程变化，详细协议见对应专题。

### 04A　持续 Agent 会话与身份

借鉴 Cue / Grok 的稳定角色和私聊、群聊，以及 Muse 的活动与成果关系，建立持久 Agent 会话、最近会话、成员管理和逐条发言身份。

工牌以可翻面的浮层呈现，支持指针倾斜、键盘焦点和工作记录。头像采用本地 DiceBear 风格，可上传或为未来角色设置默认风格；模型配置按 Agent 保存。详见[Agent 设计](revision-02/AGENT-DESIGN.md)。

### 04B　可探索认知与真实来源

关系图使用实际关系布局，支持缩放、平移、搜索、邻域聚焦与关系筛选；大图分帧计算，节点尺寸和字体保持可读。联系人以紧凑列表展示，平台作为头像角标。

人生时间轴保留日期精度，导入经过文件预览与确认。电脑活动保留 Dev 标识，微信与 WhatsApp 使用规范导入格式。详见[认知设计](revision-02/COGNITION-DESIGN.md)与[导入协议](IMPORTS.md)。

### 04C　真实模型配置与错误处理

提供方、模型 ID 与协议分别配置，界面只展示已配置连接。新增多家模型提供方预设与自定义地址，支持按 Agent 选择模型。

保存或连接检查失败时保留输入；旧响应不能覆盖新配置，已保存密钥不回读。兼容 Responses、Chat Completions 与 Messages 协议。详见[模型连接](revision-02/MODEL-CONNECTIONS.md)与[Anthropic 接入](ANTHROPIC.md)。

### 04D　项目、成果与示例空间

项目绑定可校验的本地目录，任务可以不绑定项目；远程仓库 URL 作为引用。执行记录实际工作目录，成果只收录运行器实际产生的合格文件。

重叠目录并发保护、文件列表、成果版本、外部编辑冲突与示例升级共同保护已有内容。原生目录选择、文件写入和示例空间切换经过检查。详见[项目协议](PROJECTS.md)与[示例规则](revision-02/DEMO-DATA.md)。

### 04E　个人专家与现实场景入口

专家按职责和场景组织，推荐依据来自已确认背景、当前目标和填写的说明。创建流程衔接个人问题、角色配置、工牌与会话；批量头像风格可以成为后续新建和扫码角色的默认值。

普通 HTTP(S) 链接和二维码作为来源，用户确认名字、职责和说明后保存。自动网页理解、商户订单和支付属于后续能力。详见[扫码来源](revision-02/QR-SOURCES.md)、[专家库](revision-02/EXPERT-LIBRARY.md)和[OpenMuse 取舍](revision-02/OPENMUSE-REVIEW.md)。

### 04F　跨端、资源与产品完整性 Dev

手机、眼镜与桌面围绕同一项任务设计接续流程，区分澄清、执行、审阅、离线和取消。资源场景展示电话、邮箱、预算、设备、扫码与排队的完整交互路径。

这些入口以 Dev 标识说明当前为场景演示；真实设备认证、传输和业务服务按独立集成推进。详见[设备模拟器](DEVICE-SIMULATOR.md)与[资源场景](revision-02/AGENT-RESOURCES-DEMO.md)。

### 04G　外部联系人与结构化人物画像

外部联系人资料与专家角色分开保存。人物画像按背景、关系、偏好和来源组织，支持结构化编辑、版本修订和来源回看；缺少依据的内容保持待确认状态。

联系人筛选、头像与平台角标、原文阅读及画像编辑共用实际资料。详见[人物画像](PERSON-PORTRAITS.md)。

## 2026-09-30 受限分身从角色名片进入本机调用

角色卡只提供角色描述；受限分身增加可调用的能力快照、脱敏背景、服务规则和接收者授权。每个链接或二维码有独立用途、期限、次数及只读／调用权限，支持逐次审批、结果查询和撤销。

文本执行器只接收已发布的说明与当前请求，不继承个人资料或工具。重新发布撤销旧授权，模型配置改变后需要重新发布；交付结果前再次检查授权。工程修复覆盖撤销竞态、重启状态和请求页刷新。

当前提供本机文本调用与 A2A 子集。协议与交互检查通过；远程分发和第三方互通另行推进。详见[受限分身](DELEGATION.md)。

## 2026-09-30 远端电脑与断线恢复

远端电脑配置连接 SSH 主机与指定工作区，以独立进程保存任务、审批、事件和成果。关闭本机只停止观察，重新连接查询原任务；重复请求不重跑。输入文件和模型配置按任务固定。

远端执行状态与网络连接状态分别保存，未知执行状态继续保护目录。主任务镜像与远端关联使用同一事务，避免部分写入产生孤立任务。进程、恢复与接口检查通过；真实主机需要单独配置。详见[远端电脑](REMOTE-COMPUTERS.md)。
