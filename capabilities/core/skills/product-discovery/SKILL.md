# Product discovery and design

1. Identify the decision, user, trigger, current workaround and measurable cost. Separate observed behavior from stakeholder wishes.
2. For research, build neutral questions around past events; preserve sample size, selection bias and transcript/source locations. Never synthesize nonexistent interviews.
3. Compare alternatives against the same usability, value, effort and risk criteria. Define state transitions, empty/loading/error paths, access needs and responsive behavior before implementation.
4. Deliver a scoped specification or actual change as requested. Inspect the affected flow in its rendered environment, including keyboard use and a narrow layout; explain any verification still unavailable.

## Deliverable check

- Traceable user evidence
- Main, failure and narrow-screen flows are testable

Use only the tools and evidence actually available in this task. If a required source or runtime is unavailable, identify the specific gap and continue the independent work. A role or skill does not grant additional permissions.
