# Local backend and runtime acceptance

Start with `node server/index.mjs`. The server listens only on `127.0.0.1` (`PORT`, default `58645`). `HITHER_DATA_DIR` defaults to the project's ignored `.hither/` directory. `HITHER_CODEX_BIN` can select an installed Codex executable (`HITHER_CODEX_BINARY` is a compatible alias; `BIN` takes precedence). Detection and execution use the same resolver. The backend requires Node with `node:sqlite` (tested on Node 26.3.1); an Electron host must separately verify its embedded Node and SQLite availability.

`GET /api/health` includes `spaceId`, the first 24 hex characters of SHA-256 of the resolved store directory, so a desktop wrapper can distinguish local data spaces without receiving their paths. Codex resolution honors explicit configuration, then executable entries on `PATH`, then existing common macOS Homebrew and official Codex/ChatGPT application locations. Failure of a found executable does not trigger a different runtime automatically. Closing the service during a pending demo approval leaves the task interrupted; a user's explicit cancellation remains cancelled.

The backend owns SQLite records, task state, version history, source references, scheduler state, and credentials. Credentials are stored separately in a mode-0600 file within a mode-0700 directory and are keyed by provider and URL. Bootstrap exposes only presence and a masked suffix; export contains no credential file or runtime state. No other app's credentials or configuration are read.

The fictional initial profile and sources are marked as demonstrations. Importing text creates evidence only. Source originals cannot be overwritten (`PUT /sources/:id` returns 405); a correction is a new feedback source. Facts are user-edited with optimistic revision checks, and new revisions retain their contemporaneous kind and source IDs. Older history lacking those fields remains unknown rather than being backfilled from current facts. Relationships and references are validated; a referenced record cannot be deleted before its dependents are updated. Artifacts are task-scoped regular files; traversal and symlinks are rejected. User artifact edits retain exact whitespace and every recorded version. Concurrent edits return 409; live model execution must first stop before editing an existing artifact.

## Execution modes

- `demo` runs deterministic local templates. The community audio exhibition example demonstrates cognition constraints, a plan, a draft invitation that is never sent, and a distinct reviewer checklist. Other tasks receive a general editable worksheet. These outputs explicitly state that no language model ran. A one-time approval is required before writing real files.
- `live` calls the installed Codex app-server using a separate runtime home and an explicitly configured Responses provider. Missing credentials leave a task in `needs_input`; there is no demo fallback. Each selected role has its own thread, events and output and runs sequentially with previous role output as reviewable context. This is not parallel autonomous agent coordination.
- Each run snapshots selected cognition and its revisions in the existing `context` event. A separate `evidence` event contains only sources explicitly linked to those selected facts: up to 3,000 excerpt characters per source, 12,000 total and 20 sources. Each includes the complete source text's SHA-256, excerpt and truncation flag; omitted sources are counted. The exact evidence snapshot enters the prompt as untrusted evidence, never instructions or permission. Unrelated sources are not collected. A new user message saves the correction, interrupts the old run, waits for its process to end, then continues using current selected facts and evidence. Model results never automatically change confirmed facts.
- Approvals resolve a pending request once. Rejecting or cancelling cannot approve it later; restart invalidates old approvals and marks interrupted execution honestly. A check-point/thread identifier does not guarantee external operations happen exactly once. The system does not automatically replay interrupted tasks.
- After live execution stops or fails and tool cleanup finishes, newly written text files can still be collected with `reviewStatus: pending` and an `artifact_pending` event. This never changes a cancelled or failed task to completed. Collection accepts only regular UTF-8 text files with supported extensions at the task directory's top level, at most 1 MiB per file, 5 MiB total and 50 changed files; symlinks, hidden files, nested directories and binary/oversized files are not ingested. Existing user versions are preserved on conflict. The collection boundary applies to normal runtime-created file ingestion too; generated final responses are separate artifacts.
- Enabled schedules run only while this server is online. An overdue interval produces one catch-up task, not all missed intervals. Each automation allows only one queued, running, awaiting-approval or needs-input task: manual duplication returns 409; scheduled duplication skips and advances the next time. Import triggers refer to the newly imported source; while a task is pending, later imports are saved but their trigger is skipped and recorded, not silently merged into the existing task. There is no cloud wakeup, sleep execution, cross-computer failover, or device synchronization.

## Codex boundary

`codex.mjs` implements line-delimited app-server RPC, explicit thread start/resume, streaming events, single-action approval, interruption, and process-group cleanup. A named permission profile grants minimal OS reads and task-directory writes, with tool network access off by default. The adapter verifies the effective profile and refuses unsupported runtime versions. Runtime credentials are passed to its isolated environment and excluded from the shell-tool environment; provider settings contain no key in command arguments.

The installed `codex-cli 0.158.0-alpha.2.1` accepts `on-request`; the same runtime rejects the old `untrusted` value despite a stale generated schema. Command and file approvals permit only a single `accept` or `decline`; session-wide grants and bulk permission expansion are not approved by this adapter. Unknown protocol requests are rejected, and interactive questions become `needs_input` instead of invented answers.

DeepSeek is the default editable configuration, not a product restriction. The exact model/provider's real Responses stream, tools, reasoning, context and multimodal compatibility remain unverified without the user's own key and actual calls. The settings connection test makes one explicit small text request and requires nonempty Responses text output, not merely HTTP 200. Its result is bound to the provider, model, URL, API, reasoning setting, credential identity and configuration revision. Changing configuration or credentials while a test is pending discards the stale result with HTTP 409 and never writes it into the new configuration. This does not certify tools or other capabilities. No paid model call was made during development. No ChatGPT account or Codex user login is reused.

## Evidence

`node --test tests/backend.test.mjs tests/codex.test.mjs` covers persistence, cognition corrections, references, local origin/JSON guards, credential isolation/export, real demo files, version conflicts, approval rejection/cancellation, restart honesty, source-import schedules, multi-role execution fixtures, and app-server transport behavior.

`HITHER_TEST_REAL_CODEX=1 node --test tests/backend.test.mjs tests/codex.test.mjs` additionally performs installed-runtime initialization, effective permission checks, real sandbox writes inside the task directory and denied outside reads/writes, and complete adapter setup cancelled before model execution. On 2026-09-29 the combined 29-test suite passed; two subsequent backend cases for interactive resume and cancellation cleanup also passed (12 backend cases and 19 runtime cases in total). These offline runtime checks are separate from provider acceptance and desktop/browser acceptance.

Primary implementation reference: [OpenAI app-server documentation](https://learn.chatgpt.com/docs/app-server), plus the installed runtime's generated JSON schema and the publicly archived `openai/codex` source at commit `a9118edae8b77bf23b7182fd071a7b6251898bed`. Private source materials and runtime credentials are not part of this project.
